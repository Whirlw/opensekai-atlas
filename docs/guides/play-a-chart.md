# 打一首歌

> 目的：从「手上有一首自制谱」到「看到结算」，把曲库、加载、live、暂停、结算、历史这条链路讲全。
> 适用读者：使用者、测试者。
> 前置条件：已启动 Android 应用或在 Unity 中运行项目。 [环境与运行](../getting-started/build-and-run.md)
> 最后更新：2026-11-20

## 概述

从首页进入「曲库」游玩已保存的谱面，也可以从 Sonolus 服务器详情直接游玩。曲库从应用用户数据目录下的 `CustomMusicScores/` 读取已安装曲包。 [服务器使用指南](server-chart-downloads.md)

## 核心内容

### 曲包放哪

```text
%USERPROFILE%\AppData\LocalLow\OpenSekai\OpenSekai\
  CustomMusicScores\
    <曲包目录>\
      manifest.json    曲名、难度、等级等元数据
      score.json       谱面（示例为 JSON）
      audio.ogg        音轨
      jacket.jpg      封面（可选）
  PlayHistory.jsonl    打歌历史（由游戏写入，不在曲包目录内）
```

字段定义见 [曲包格式](../architecture/chart-package.md)。

### 三种进入方式

| 方式 | 操作 | 备注 |
| --- | --- | --- |
| 导入 ZIP | 头部「导入 ZIP」，选一个 `.oskp` 或 `.zip` | 桌面用 StandaloneFileBrowser，移动端用系统文件选择器 |
| 导入文件夹 | 头部「导入文件夹」 | **移动端隐藏**（`LibraryImport.SupportsFolderPick` 为 false） |
| 手动放入 | 直接把曲包目录拷进上面的 `CustomMusicScores/`，点「刷新」 | 最稳，任何平台都能用 |

导入失败时页面底部状态栏会给出中文原因（例如「无法读取所选文件。」），不会静默失败。

### 管理曲包：更多 / 排序

每行最左边是「更多」，点开是一张浮层卡片，三个按钮从上到下：

| 按钮 | 行为 |
| --- | --- |
| 导出 ZIP | 把曲包打包成 `.oskp`。桌面弹保存对话框（默认文件名取曲名）；移动端没有保存对话框，写到 `CustomMusicScores/Exports/<曲名>.oskp`，状态栏给出完整路径 |
| 删除曲包 | 首次点击只把按钮改成「再点一次确认删除」，第二次点击才真正删除并刷新列表 |
| 取消 | 关闭浮层 |

曲库默认按标题排序且不分组。可以从工具栏调整排序、分组，或切换网格与栏目视图。调整会保存到设备，重启后恢复。

在「分组」中选择「Ranked 状态」，即可按 Ranked、Unranked 或「待确认」筛选曲包。分组使用本地核验记录。核验完成后，对应分组和数量会自动更新。

Ranked 曲包带金色的「RANKED」标签，AP / FC 的曲包带彩色徽章。栏目视图里两者在难度标签左侧，依次为 AP / FC、RANKED、难度。网格视图中，RANKED 在封面左上角，难度和等级在右下角，AP / FC 紧挨在难度左侧。

曲包详情右上角的按钮有三种状态：

| 按钮 | 何时出现 | 点击后 |
| --- | --- | --- |
| 详情 | 已有 Ranked 记录，或来源不提供 Ranked | 打开「谱面详情」。顶部横幅显示「-Ranked-」或「-Unranked-」，下方有状态说明和可复制的来源链接。支持 Ranked 核验的来源可点「刷新 Ranked」。右下角「Ranked 规则」列出完整规则 |
| 检查 | 有来源链接且 Ranked 状态未知（待确认） | 联网核验一次，记录结果后变为「详情」。收到无法解析的数据时记为 Unranked，十分钟后可从详情页刷新。网络失败可立即重试 |
| 详情（灰色） | 没有来源链接 | 点击后在按钮下方提示缺少来源链接 |

### 开局

- 点「手动」：正常打歌，判定按输入计算。
- 点「自动」：AUTO 模式，音符全部自动命中，用于验证谱面与特效。

点下去后出现加载浮层（标题 + 进度文案 + 取消）。文案依次是「正在读取谱面...」「正在加载音频...」
「正在开始游玩...」（自动模式是「正在开始自动游玩...」）；点「取消」回到发起游玩的页面。

### 跳过前奏与尾奏

手动与自动演奏使用相同规则。前奏和尾奏的跳过键都只在还能显示至少 1 秒时出现。前奏按钮在首键前 2 秒消失，点击会直接跳到该时刻。

尾奏按钮最早在末键后 1 秒出现。自然播放时，等可听音乐和末键都结束，再过 1 秒，普通谱面播放结算特效，段位谱面直接渐变为黑屏。点击尾奏跳过键会立即开始对应的演出或渐黑。

### 演奏中的暂停

左上角暂停按钮 → 浮层「暂停 / 曲名」+ 三个按钮：

- 继续：回到 live
- 重开：从头开始同一首
- 退出到曲库：按**中途退出**结算（不是失败），历史不写入

### 结算

结果面板显示：曲名、`(自动|手动) · Lv.N · 原因`、大分数、评级、最大连击/总音符、判定分布、两个按钮。

| 原因 | 触发 |
| --- | --- |
| 完成 | 谱面跑完且未失败 |
| 中途退出 | 暂停里选「退出到曲库」 |
| 失败 | 生命值耗尽 |
| 加载失败 | 曲包读不出来，面板只显示失败原因，不显示分数 |

「再玩一次」用同一曲包重开。从曲库开局可返回曲库。从服务器开局可返回原谱面详情，并在详情页下载。

### 自动模式的三个特殊表现

默认自动模式使用 Auto 判定：

1. **默认连击为 0**：`ScoreLogic.UpdateCombo` 里 `effectiveResult < NoteResult.Great` 就把连击清零，而 `NoteResult.Auto`
   低于这个门槛。
2. **判定计数全 0**：`UpdateNoteResult` 对 Auto 只累加 `autoCount`，手动评级的计数保持为 0。
3. **不写历史**：只有已安装谱面的手动完成成绩保存到本地。临时游玩后下载曲包时，先前的成绩不会补写。

因此自动打歌的满分是 `1,000,000`（累积摊分后严格成立），但面板上显示的是「总音符 2019 · 自动判定 2019」而不是各级判定。

## 详细说明

### 分数怎么算

单个音符的基分不是 `1,000,000 / 音符数`，而是按**累积摊分**：第 i 个音符（0 基）拿
`round(1e6 * (i+1) / n) - round(1e6 * i / n)`，所以 n 个音符全打满时总和严格等于 1,000,000。
Perfect 和 Auto 得到音符基分的 100%，Great 得 85%，Good 得 50%，Bad 得 20%，Miss 得 0%。开启减法分数后，局内从 1,000,000 分扣除每次判定损失的分数。暂停后中途退出时，结算页显示已获得的分数。

细节与修复原因见 [ADR-0004](../decisions/0004-cumulative-scoring.md)。

### 历史记录

写盘位置与曲包同级的 `PlayHistory.jsonl`，每行一条 JSON，包含分数、判定分布、清关类型、
`chartHash`（谱面文件 SHA-256）、`rulesVersion`（当前 2）、`sessionId`。

## 示例

导入一首歌并自动验证：

```text
1. 把曲包目录拷进 CustomMusicScores/
2. 曲库页点「刷新」→ 行出现，标题与 Lv 正确
3. 点「自动」→ 加载浮层 → live 开始
4. 打完 → 结果面板 1,000,000 / S / 完成
```

## 常见问题与故障排查

- **导入后列表里没有**：确认目录层级是 `CustomMusicScores/<任意目录>/manifest.json`，不是再多套一层。
- **点开局后停在加载浮层**：看状态栏文案停在哪个阶段；「正在加载音频...」卡住通常是音频文件缺失或格式不支持。
- **结算显示「加载失败」**：曲包元数据或谱面 JSON 解析失败，面板上的 `Message` 会给出原因。
- **手动打歌分数不满 1,000,000 但全是 Perfect**：核对整首谱面的判定点是否都已计分。
