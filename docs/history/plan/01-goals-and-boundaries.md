# 方案：结论、起点与边界

> 目的：记录重构方案的结论、当时的工程起点与产品边界（为什么只保留打歌）。
> 适用读者：开发者。
> 前置条件：先读 [方案索引](../player-lite-plan.md)。
> 最后更新：2026-11-02（仅按章节拆分为独立文件，正文未改）

> 这是设计稿的一个分册。全文索引与「现状对照」见 [方案索引](../player-lite-plan.md)。

## 1. 推荐结论

将项目收敛成一个**本地曲包播放器与单人音游客户端**：

**启动 → 曲库 → 选择歌曲 → 手动／自动游玩 → 暂停／重开 → 结算 → 返回曲库。**

推荐采用“**复用现有直玩入口和 Live 内核，抽离谱面兼容层，替换编辑器应用外壳，再按依赖裁剪资源与空壳**”的路线。

关键判断：

1. **不用重新实现直玩。** 首页已经有 `PlaySelectedAsync` 和 `CreateDirectPlayBootData`，可以绕过编辑界面进入 Live。应将其提取成应用服务，作为新主流程。
2. **不能直接删除 `MusicScoreMaker` 整个目录。** 曲包模型、JSON 读取、时间转换、长条构造和播放历史仍位于其中。先抽出这些能力，才能删干净编辑器。
3. **优先保持打歌语义。** 首轮保留现有音符模型、判定窗口、计分规则、音符对象池和音频后端；先处理启动、状态、资源所有权和热路径分配。
4. **将手感修复单独验收。** 输入时间换算有明显疑点，但音频时钟、输入回推、判定窗口不能同时改，以免回归后无法定位原因。
5. **默认轻量发行包排除视频生成。** 这是一项范围建议，不是用户已要求删除的功能；录屏工具链可作为独立可选模块保留。曲包自带 2D MV 的播放与视频生成分别处理。

轻量化的验收同时覆盖代码依赖、玩家流程、运行开销和最终构建体积，不能仅以删除文件数判断成功。

## 2. 当前项目的真实起点

### 2.1 文档与代码需要对齐的地方

文档以“编辑器 → 试玩 → Live”为主线，但当前代码还存在一条可以直接复用的流程：

```text
ScreenLayerCustomMusicScoreManager.PlaySelectedAsync
  → CustomMusicScoreEntry.LoadScore
  → RegisterAudioAsync
  → CreateDirectPlayBootData
      → MusicScoreMakerData.ToMusicScore
  → UserDataManager.FreeLiveBootData
  → LiveLoading → Core → SoloLiveController
```

所以任务的主要工作是**将已经存在的直玩链路从编辑器体系中独立出来**。

### 2.2 必须解除的耦合

| 当前耦合 | 代码事实 | 对重构的影响 |
|---|---|---|
| 应用入口属于编辑器 | 首个构建场景是 `MusicScoreMaker.unity`，入口是 `MusicScoreMakerEntryPoint` | 删除场景会一起丢掉字体、输入、音量、资源和首页初始化 |
| 曲包读取返回编辑器模型 | `CustomMusicScoreEntry.LoadScore()` 返回 `MusicScoreMakerData` | 删除编辑器模型会让已有曲包无法播放 |
| 播放转换夹在可编辑数据模型中 | `MusicScoreMakerData.ToMusicScore()` 依赖 `MusicScoreMakerUtility` 和模型常量 | 需要提取转换算法，不能只移动一个类 |
| 公共工具混有 UI 与事件总线 | `MusicScoreMakerUtility` 引用编辑器 Events、Views、Settings | 整体搬到“公共层”仍会把编辑器带回来 |
| Live 直接引用编辑器 Presenter | 暂停、全连确认、发布、返回使用编辑器 BootArg | 删除 UI 前必须移除这些分支 |
| 返回曲库仍加载编辑器场景 | `SoloLiveController.OnExit()` 把首页返回目标映射到 `Scene.MusicScoreMaker` | 替换入口时必须同步改返回路径 |
| 首页承担过多职责 | 曲库、表单、设置、编辑器恢复、直玩和视频生成集中在一个类 | 应按曲库页面、设置页面与开局服务拆分 |
| 录屏侵入 Live | `SoloLiveController`、`LiveLogic` 识别 `VideoGenerationBootData` | 要让轻量构建不依赖录屏类型 |
| 资源按标签全部构建 | AB 构建入口读取 `GetAllAssetBundleNames()` | 仅隐藏编辑器按钮不会使相关 AB 自动退出构建 |

《项目总览》记录编辑器约 536 个文件、5.8 万行；这是文档盘点口径，其中包含仍需保留的数据与转换能力，不能当作可直接删除数量。本文不据此承诺包体积降幅。

## 3. 产品边界与功能取舍

以下是建议采用的第一版范围。未在本方案内扩展联网、账号、商业游戏外围系统或全新玩法。

| 功能 | 建议 | 具体边界 |
|---|---|---|
| 本地曲库、选曲、封面、难度信息 | 保留并简化 | 首页以选曲为中心；维护表单移到曲包详情 |
| 曲包文件夹／ZIP 导入、ZIP 导出 | 保留 | 复用现有格式和文件选择能力 |
| 旧 `score.json`、SUS／TXT 导入 | 保留 | 无需用户重新制谱；明确 TXT 指 SUS 文本 |
| 手动与自动游玩 | 保留 | 自动模式明确标识，不更新手动最佳成绩 |
| Tap、Flick、Long、Friction、Guide 等现有形态 | 保留 | 保留 Critical、装饰音符、连线与既有组合行为 |
| BPM、HighSpeed、SE 音量、单键变速、负流速 | 保留 | 重构不得以轻量化为由丢弃已支持的谱面表现 |
| 暂停、倒数恢复、重开、退出 | 保留 | 同时覆盖菜单操作、返回键和移动端切后台 |
| 分数、连击、血量、判定统计、FC／AP | 保留 | 沿用现有规则，新增紧凑的本局结果页 |
| 延迟、流速、音量、皮肤、打击效果、高帧率 | 保留 | 独立设置入口；旧设置继续读取 |
| 曲包封面背景 | 保留并作为轻量默认建议 | 无封面时使用通用背景 |
| 曲包自带 2D MV 播放 | 可选保留 | 按需加载；关闭后不初始化视频解码和相关 RT |
| 谱面编辑、创建、预览编辑、撤销、剪贴板、自动存档 | 删除 | 删除玩家入口、脚本、场景与独占资源 |
| 编辑器试玩、全连发布检查、草稿、发布流程 | 删除 | 统一为普通游玩与普通结算 |
| 曲包替换谱面／音频、修改元信息 | 保留基本维护能力 | 属于文件导入与包管理；删除编辑时长、波形编辑等工具入口 |
| 备份恢复、已有播放历史 | 保留 | 区分曲包备份与已停止使用的编辑器数据 |
| 视频生成、录音、转码、相册保存 | 从默认轻量构建排除 | 可选工具模块保留源码；禁止侵入核心判定循环 |
| MultiLive、Rank、3D MV、角色技能／卡组外围、无 prefab 的页面 | 按实际依赖裁剪 | 不为不可达骨架补全功能；先解除类型引用再删 |
| OTA 更新检查 | 从默认启动移出 | 本地游玩不依赖旧更新服务；后续需要时作为独立能力接入 |

**“去掉谱面编辑器”不等于“去掉自制谱支持”。** 第一版继续消费外部制作的曲包，且不改写用户原始谱面。
