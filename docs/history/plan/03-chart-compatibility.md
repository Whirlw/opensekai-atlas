## 5. 谱面兼容：这次重构最重要的工作

### 5.1 第一版保留曲包格式

第一版继续读取：

```text
CustomMusicScores/<现有目录>/
  manifest.json
  score.json 或外部导入的 score.sus／score.txt
  audio.ogg／mp3／wav
  jacket.png
  可选 video.*
```

保留现有包 ID 和 `custom_<id>` 音频 cue 规则，避免历史记录与曲包失联。暂不设计强制升级的 v2 曲包格式，也不把运行时对象直接序列化为新存档。

### 5.2 抽离的具体内容

从 `MusicScoreMakerData`、`MusicScoreMakerUtility` 及相关数据类中提取：

1. 实际存储字段与版本迁移规则，形成只读的旧格式 DTO／读取器。
2. tick、BPM、拍号与播放秒数的转换。
3. 音符连接关系、长条头尾、中间点、长按连击点的构造。
4. 同时押线、Flick 方向、Guide、Critical、装饰标记与颜色。
5. 单键速度、全局速度、负流速和已有的生成顺序／排序规则。
6. 从读取结果创建现有 Live 音符的转换逻辑。

留在删除范围内：选中集合、拖拽增量、撤销栈、复制内容、预览缩放、编辑器窗口状态、自动存档定时器和发布校验。

`LaneCount = 12`、tick 常量等移到独立常量类，不能再通过 `MusicScoreMakerModel` 获取。

### 5.3 旧 JSON 不能靠改名字解决

旧 JSON 使用 `PreserveReferencesHandling.Objects`、`TypeNameHandling.Auto`，可能包含 `$id`、`$ref`、`$type`。移命名空间或程序集可能使旧文件失效。

建议：

- 使用专门的 `LegacyChartReader`，按实际旧类型建立受限映射；需要引用恢复时保留相应解析能力。
- 允许的类型集合来源于旧 DTO 和实际使用的事件类型，不允许任意类型自动实例化。
- 从恢复后的旧数据映射到 `ChartDocument`，忽略编辑状态；不使用文本替换或直接删除元数据的方式迁移。
- 对未知版本、无法解析的类型、损坏引用返回具体错误，不创建空谱并假装导入成功。
- 读取、缓存和校验均不覆盖源 `score.json`。导入转换写入暂存文件，验证成功后才提交。

过渡阶段可以暂时保留少量旧命名空间 DTO，等读取器覆盖完成再移除。允许兼容层识别旧类型名称，不允许核心运行时继续调用编辑器实现。

### 5.4 SUS 路径尤其需要做等价验证

目前路径是：

```text
SUS → Converter.Convert(isNeedCombo: false, overrideMirror: false)
    → MusicScoreMakerData → ToMusicScore → Live
```

不能直接改成“SUS 转出的 MusicScore 原样播放”就视为完成；当前中间转换还会生成长按连击点、规范长条形态等。

第一阶段保留这些语义，将所需转换抽出来。之后才考虑直接生成统一文档或运行时定义。重点比对长条连击点、头尾类型、Guide、事件顺序、同时押和镜像是否只应用一次。

### 5.5 区分兼容保持与缺陷修复

当前 `ToMusicScore()` 会在转换副本中移除原拍号事件并补入 tick 0 的 `4/4`。这与泛化的“支持任意拍号”并不等价。

首轮应将这种实际行为写入兼容基线，不在抽离过程中顺手改变。随后若修复非 4/4 行为，应作为独立变更，使用明确的样例和新旧结果差异验收。其他时间轴边界也遵循这一原则。

### 5.6 转换只发生在导入或加载阶段

UI 不直接反序列化谱面；由读取器、校验器、转换器组成单一入口。缓存键至少包含源文件内容哈希、转换器版本及会影响结果的选项。

需要 Unity 对象或配置的部分在主线程完成；文件读取和纯计算可独立调度。局内不执行 JSON 深拷贝、磁盘扫描或全谱转换。缓存是可丢弃的派生数据，失败后可以重建。
