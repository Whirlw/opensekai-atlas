## 9. 资源、依赖与构建瘦身

### 9.1 按真实可达资源裁剪

建立资源入口白名单：Library 场景、Core 场景、必要过渡场景、保留页面、Live HUD、音符皮肤、打击特效、通用字体与音效。

结合静态引用和运行时字符串加载清单求依赖闭包。`Resources.Load`、AssetBundle 名、图集 Sprite 名、配置表与反射路径都可能绕过普通引用扫描，不能只用“没有 prefab 直接引用”判断可删。

### 9.2 候选资源分组

| 分组 | 候选内容 | 验证要求 |
|---|---|---|
| 编辑器独占 | 编辑器场景、ScreenLayerMusicScoreMaker、预览 prefab、量化线、工具图标、编辑器专属弹窗与图集 | 新曲库／Live／旧谱兼容层无引用后移除 |
| 不可达外围 | 抽卡残留、无 prefab 的注册项、Multi／Rank／3D 页面及对应空壳 | 检查共享图集、UI 基类与配置引用 |
| 默认关闭的重表现 | 多套结算演出、常驻点击特效、大加载背景 | 可用简单结果／淡入淡出替代；保留必要反馈 |
| 必须保留 | 音符、判定线、长条与引导材质、打击反馈、必要字体与通用 UI | 低画质只降低特效密度，不能损伤判读 |
| 渲染基础资产 | URP 配置、LUT、SMAA 纹理、必要 Shader／RendererFeature | 不能因混在 Texture2D 中而当作无用美术删除 |
| 可选录屏 | VideoGeneration、编码器、录音、后处理、输出 UI、相关专用权限与 ffmpeg | 编译隔离后从轻量发布清单排除 |

两套音符皮肤第一版均可保留。是否裁为一套应根据实测大小与用户价值判断，不预先制造皮肤兼容问题。

### 9.3 构建规则必须跟着改

现有 AB 流程构建所有已配置标签，因此需要一个轻量构建配置，限制根 bundle 并带上其递归依赖，或在资源删除完成后清理失效标签。

构建到干净的目标目录，生成并核验当前 manifest，防止旧 `StreamingAssets/data` 残留继续被复制。不能简单复制上一轮输出后覆盖少量文件。Android 继续验证 jar 内资源的实际加载路径。

`ffmpeg/` 约 185 MB 是文档记录的仓库目录大小。将它排除出轻量发布能减少对应分发内容，但**不意味着 APK 必然减少同样大小**：必须先确认现有发布步骤是否真的包含它，并分别统计仓库、Player、StreamingAssets、发布附件。

保留脚本／资源迁移时的 `.meta` GUID。旧资源完成解绑后再删，不手工生成替代 GUID。

### 9.4 第三方依赖分批处理

- 保留 Unity 2022.3.62f3 与当前 URP 版本作为基线，本轮不升级引擎。
- UniTask、TMP、Input System、DOTween、当前使用的 UI 与文件选择能力先保留。
- MessagePack、uPalette、SoftMask、UI Particle 等按实际序列化标记、组件与保留 prefab 的依赖评估，不能因编辑器移除就直接卸载。
- CRI 官方运行时、ZString、无用 Unity 包与平台库列为候选；每批移除后独立编译并构建。
- 项目开发工具与发行运行时依赖分别统计；开发插件的仓库占用不等于 Player 开销。

资源归属与第三方说明沿用 README 的记录；资源替换不与本轮逻辑重构混为一个任务。

## 10. 用户数据与兼容迁移

| 数据 | 第一版策略 |
|---|---|
| `CustomMusicScores` 与曲包 ID | 原位置读取，不重命名曲包 ID，不批量重写谱面 |
| `ApplicationLocalSettings.json` | 保留音量等有效设置，补齐缺省值 |
| `LiveSettingData.json` | 保留延迟、流速、皮肤、帧率及旧 Use120FPS 迁移语义；忽略已删除工具设置 |
| `PlayHistory.jsonl` | 向后读取，新记录追加版本信息；坏行单独跳过并记录日志，不使整份历史不可用 |
| `music_score_maker/`、编辑器偏好、剪贴板缓存 | 停止生成，不自动删除已有数据 |
| `SavedVideos`、既有备份 | 保留用户文件；轻量版不依赖它们启动 |
| 新索引／转换缓存 | 单独版本化，可安全失效重建，不作为唯一数据源 |

如果更改 companyName／productName 或数据目录，另做显式旧路径发现与迁移；首轮推荐保持原有路径，避免看起来像“曲库丢失”。

已有编辑器草稿不等于完整曲包，可能缺少独立音频与 manifest。第一版保证不删除草稿，但不承诺所有草稿自动变成可玩歌曲；可另附一次性迁移工具，在音频可定位时导出为曲包，输出成功与失败清单。

导入和替换采用“暂存 → 校验 → 提交”，失败保留旧文件；ZIP 解压校验目标路径、文件总量与展开体积，避免导入过程破坏曲库。文件检查只针对实际导入边界，不扩大为无关的安全系统建设。
