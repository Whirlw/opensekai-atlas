## 3. 头：已完成 / 未完成

### 已完成

- **按下即判**：`LongNoteHead.TryJudge` 自己 `Settle`，结果由 `LongNoteHead` 持有，条的状态机不参与。
- **窗口过期兜底**：`LongNote.Excute` 每帧调 `Head.SettleExpiredHead(currentFrameInfo.time)`，超过 `LiveConfig.JudgeTime` 且未结算就补 Miss（`LongNoteHead.cs:59-65`）。
- **静默结束要等头**：`LongNote.CanFinishSilently` 里 `if (PublishesHeadMiss && !Head.IsSettled) return false;`（`LongNote.cs:283-293`），注释写明是为了让头先发布。
- **过线未按**：`Last → Release` 那一段仍然发布头（现在走 `LeavePlayState()`）。
- **单一出口 `LongNote.LeavePlayState()`**：过线（`Excute` 的 `Last → Release`）、窗口超时（`LongNoteHead.SettleExpiredHead`）、`ForceTerminate`、`FinishSilently` 四处全部走它，它只做一件事——`Head.PublishHeadMiss()`。重复发布仍由 `Head.Settle` 的 `_headPublished` 挡。**池回收刻意不在此列**：`ResetNote()` 是复用，不是离场，在那里发布会把 Miss 写进下一局。
- **两条验收用例已写**：`ABarThatCrossesTheLineUnpressedStillPublishesItsHeadMiss`、`ABarFinishedByItsTailStillPublishesTheHead`，在 `Assets/Tests/EditMode/Live/DecouplingAcceptanceTests.cs`。两条都断言「头结算且恰好发布一次」：前者走时钟（无人按），后者按住到尾、由尾结束整条。
- **出口的三条用例**（`Live/HeadDecouplingTests`）：`ABarEndedBeforeItsHeadIsJudgedStillPublishesTheMiss`（条在头结算前被 `ForceTerminate(tail)` 结束 → 头补 Miss 且发布一次；**这一条是先红后绿**）、`AnEndingAskedTwiceStillPublishesTheHeadOnce`、`APressOnAFinishedBarChangesNothing`。
- `LongNote.DriveJudgmentFrame` 把一帧输入串成 head → 持有 → 中间点 → 尾（`LongNote.cs:186-218`）。

### 未完成

1. **Test16 真机 7/7 没有任何记录**。`device-acceptance-checklist.md` 里也没有这一项。

### 已定（原「未完成」里的判断项）

- **`LongNoteHead.TryJudge` 的 `State == Done` 早退：保留**。输入路径早已在 `LongNote.IsJudgment` 挡掉 `Done`，而条离场时头必然已发布，所以这行到不了「头还没结算」的情况——它是冗余的第二把锁，不是答案。删掉它只会让直接调用者（测试、调试）能驱动已结束条的子音符，不值得。理由写在 `LongNoteHead.cs` 该行上方，用例是 `APressOnAFinishedBarChangesNothing`。
- **`ForceTerminate` 当前状态其实到不了**：能进来的状态要么 `Last`/`Release`（此时头已被 `SettleExpiredHead` 结算），要么手指还在（手指在就是按下过）。所以这条缺陷现在是**不可达的潜在缺口**，出口的用例直接摆出那个状态来证明出口本身；不要因为它不可达就把出口删掉。
