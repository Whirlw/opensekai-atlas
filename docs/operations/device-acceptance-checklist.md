# 真机验收清单（判定相关）

用途：每次改动判定/长条/划键后，用一页清单在真机上过一遍。
前置：装机包已安装；准备一张长条密集谱（BOF）、一张普通 4/4 谱、一张带 2D 背景的谱、一张 friction 头较多的谱。
约定：每项勾选后可备注「异常现象 + 大概时间点」，便于从 `live-*.log` 取证。

## A. 长条（普通头）

- [ ] 按住期间条保持亮色，不闪灰
- [ ] 松手后先灰、约三帧后消失
- [ ] 灰掉期间（三帧内）再按住，条恢复亮色并可继续
- [ ] 尾判上屏，尾键在结算当帧消失，不留在判定线上
- [ ] 一整条打完连击数与中间点数一致（不跳、不重复）

## B. 长条（隐藏头 / 装饰条 / friction 头）

- [ ] 隐藏头：不按也不掉血、不断连击，条按时变灰消失
- [ ] 装饰条：本体不吃判定，只有尾键可判
- [ ] friction 头：按上去连击**逐点 +1**，不整批跳（2026-11-10 修复项，重点回归）
- [ ] friction 头：手动与自动下，头到线被判定的那一帧键即消失并播放 friction 判定特效，条身继续；没人碰的头越过判定线，Miss 时消失
- [ ] friction 条持续摩擦时不断连击、不掉血

## C. 划键

- [ ] 正确方向划：判 Perfect 上下，方向判定正确
- [ ] 反向划：封顶 Great（不出 Perfect）
- [ ] **提前划**（尾前 125 ms 内）：只出 1 个判定，**不出额外 Miss**、连击保持（重点回归）
- [ ] 超出提前窗口的划：不判、也不延迟
- [ ] 快速划（只有一帧 Ended 采样）：仍能判

## D. 中间点（两条长条重叠）

- [ ] 两条重叠时长条：各自的中间点各判一次（连击 +2，不是 +1 也不是 +更多）
- [ ] 过期中间点（手指晚到）：不被补判

## E. 普通键 / 综合

- [ ] 单键：Perfect/Great/Good/Miss 四档都能出
- [ ] 多指同时按不同轨道：各判各的，不互相抢占
- [ ] 长按换手：换手瞬间不断连
- [ ] 变 BPM / 变流速谱：note 位置与判定点对齐（2026-11 前后改动项）

## F. 结算与生命周期

- [ ] 整首结束：分数、评级、最大连击与预期一致
- [ ] 中途退出：回曲库正常，再次进入同一首不残留上一局状态
- [ ] 连续打两首：第二首不出现「池未复位」类异常

## G. 音频输出延迟

- [ ] 启动日志 `adb logcat -s Unity` 中有一行 `[AudioOut]`：`rate` 等于 `native` 的采样率，`dsp` 是 `native` burst 的整数倍；记下 `lowLatencyFeature` 与 `outputs`
- [ ] 外放与有线耳机下，打击音与按下的间隔主观上无明显拖尾；若 `outputs` 含 `bluetooth`，额外延迟来自蓝牙链路，不计为缺陷

- [ ] 设置里「音频延迟」「画面延迟」「判定偏移」三个输入框可输入整数毫秒（可带负号），关闭重开后保留；旧版本的「判定延迟」已自动换算到「音频延迟」
- [ ] 音频延迟设 +50：音符与判定一起变晚；画面延迟设 +50：音符提前到线、判定手感不变；判定偏移设 +50：画面不变、晚 50 ms 的按下判为正中

## 失败时怎么办

1. 记下谱面名 + 失败项 + 大致秒数。
2. `adb pull /storage/emulated/0/Android/data/io.github.opensekai/files/logs/live-*.log`
3. 按时间点定位 `LiveTrace` 行（`Tail`/`Swipe`/`Hold`/`ComboPoint` 类别）。
