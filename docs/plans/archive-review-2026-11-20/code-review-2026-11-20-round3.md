### M08（两个数字复算无误 + 一处编辑指控）

- **MAC 复算**：48 kHz × 180 s × 2ch = 17,280,000 输出样本、PCM 69,120,000 字节；每声道 67,500 个 128 样本块、全曲 135,000 块 × 16,384 乘加 = **2,211,840,000 MAC**（≈22.12 亿）；乘、加分开计 = 4,423,680,000（≈44.24 亿次运算）。对应 `HcaDecoder.cs:763-768` 与 `:92`。
- **扫描次数复算**：一次成功 `Play` = **3 次**（`755 → 728`、`812 → 1397 → 728`、`1398`；关键是 `EnsureAudioListener` 第一句就是 `EnsureInitialized`，所以它自带 2 次）；守卫 `LateUpdate` 有外部监听器 = **1 次**（`1441 → 1443` 提前返回）、无外部 = **3 次**（`1441`、`1447 → 1397 → 728`、`1398`）。旁路另计：`Play` 早退 `clipCount == 0` = 1 次、clip/clips 为空 = 0 次、`CriAtomPlugin.InitializeLibrary` 一次性 = 1 次。三处都落在 `CriAtomShim.cs:1452` 的 `FindObjectsByType`。
- **「第二节表格误贴 MAC」——指摘成立，但已在我方修复前发生**。对方读到的版本里 `M08-4` 行确实被 `M08-3` 的结论文本覆盖（我用 `replace_all` 时的失误），文件 mtime 15:34:18 晚于对方复核文档的 15:32:34，所以它读到的是修复前的快照；现行文本已是「接受，我方少算一次（Play 恒 3 次；守卫 1 或 3 次）」。**结论：「扫描次数」与「MAC 数量级」必须分别记录，不能用后者冒名顶替前者。**
