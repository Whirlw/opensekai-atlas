### M08（全接受，级别不变；补验收口径与限定语）

- **解码耗时的验收（M08-3）**：跳过路径有码为证——多包入口 `CriAtomShim.cs:254-257` 命中外部 `AudioClip` 直接返回；单包路径 `:236-245` 是两级缓存；多包路径 `:348` 命中 entry 缓存。曲包 OGG 正是经 `PackageAudio.cs:39` 注册成外部 clip，**所以打歌 BGM 常常根本不进 HCA**，命中时既不解码也不分配 69 MB。测量要覆盖两条首次解码时机——`AudioCatalog.PredecodeSoundBundle`（包加载预载）与 `MusicReady → PrepareIngameBGM`（`:292`），各记**阻塞毫秒与峰值内存**；另加一条「外部 clip / 缓存命中」对照用例，**断言 `Decode` 调用 0 次**。
- **监听器验收（M08-4）**：稳态 0 次扫描只是性能面，接管/释放是功能面，要写五点——① 无外部监听器时，首次 `Play` 后在 `_root` 上建出并启用 fallback（`AudioListener.enabled == true`）且有声音；② 启用一个外部监听器后，下一帧 `LateUpdate` 走 `1441→1443` 销毁 fallback，**场景恰剩 1 个 `AudioListener`**（不能双监听器串音）；③ 外部监听器 `enabled=false` 或 `SetActive(false)` **不算外部**（`1456` 要求 `enabled && activeInHierarchy`），fallback 必须重建并启用、不能静音——**这条最容易漏测**；④ 外部监听器被销毁（切场景相机消失）后 fallback 重建；⑤ 稳态每帧 0 次 `FindObjectsByType`，且 `EnsureAudioListenerGuard(1433)` 不重复挂组件。改事件驱动后这五点即回归基线——**不能把「只在变化时扫」做成「永远不再扫」**。
