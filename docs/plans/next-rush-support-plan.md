## 1. 目标与范围

在现有 JSON / SUS 加载器之外，完善 NextRUSH+ 原生加载器，使目标版本合法谱面的音乐同步、音符、连接几何、变速和舞台效果能够在 OpenSekai 正确运行。保留原始 LevelData，复用共同播放、输入、曲库与结算基础设施。

本文的“完整支持”指固定版本下的谱面播放语义，排除用户明确要求忽略的技能与 Fever。它不表示实现 Sonolus 虚拟机、服务器排行榜、联机、Sonolus replay/watch/编辑器或任意 Sonolus 引擎，也不承诺任意第三方皮肤的逐像素复刻。资源缺失允许使用本项目等价素材，但不能丢失表达玩法所需的方向、颜色、透明度和舞台几何。

完整支持需要同时满足：

1. 目标版本的所有谱面输入实体和字段都有明确处理规则。
2. 音乐偏移、变 BPM、分组变速、连接和附着关系正确，表现与判定使用一致的几何来源。
3. 真实输入能正确完成全部音符类型；Fake、Anchor 不进入成绩，隐藏判定点只计一次。
4. 技能与 Fever 被明确忽略；它们不阻止播放，也不改变生命、判定、计分或演出。
5. Windows 和 Android 均通过真实谱面、手动操作、同步与性能验收。
6. 原有 JSON / SUS 的行为和历史成绩可继续使用。

### 1.1 固定上游版本

调研时 UntitledCharts 返回的引擎标识为 `NextRUSH_P`，资源版本为 13，描述为 NextRUSH+ v2.19.1。这些元数据不能单独证明服务器部署内容与 GitHub master 一致。

源码研究基线固定为上游提交 `1f086fb6fcc56fcb38cbf9eba6b98dbefc630316`。阶段 0 必须记录样本的 engine 元数据及资源 hash，核实其与源码基线的差异；不能将“支持 master”作为无限扩展的承诺。后续上游升级以新的兼容档案和回归结果进入支持范围。

### 2.1 两个需要纠正的假设

- 隐藏中间点可以复用，但 Anchor 不限于长条内部：它还可能是装饰端点，不能强制套进“可判定头 → 中间点 → 可判定尾”的链。
- 初版将缺省 Initialization revision 视为 2。P0 中按固定源码校正为 `SONOLUS_1_1_0 = 1`，并记录 revision 0/1/2 对计分和高度的影响。具体运行时规则分别随计分和舞台阶段接入。

## 3. 架构方案

```text
原始 LevelData + 来源信息
  → NextRushChart（语法解析、保留原始字段）
  → NextRushValidator / CompatibilityReport（按 revision 检查与归类）
  → NextRushCompiler（编译时间线、引用图、几何、玩法定义）
  → RuntimeChartDefinition（MusicScore + 可选原生运行时数据）
  → PlaySession → Live（时钟、输入、表现、成绩）

旧 JSON / SUS → 现有转换器 ───────────────→ 共同运行时
```

以上新增类型是建议职责名，实施时按现有命名规范落地。避免继续把所有时间线、舞台和玩法分支堆进单个 Builder。

### 3.1 分层与复用

- **Core**：原始实体、引用索引、revision 规则、BPM/变速/舞台事件的纯数据与数学、兼容诊断。原始字段保持可追溯，不执行外部脚本。
- **App / Infrastructure**：文件读取、编译编排、曲包来源与错误提示，组装运行时数据。
- **Game**：输入和判定策略、每帧原生位置求值、连接绘制、舞台投影、生命周期与成绩发布。
- **既有能力**：复用浮点轨道、NoteBase、隐藏中间点、Guide、长条视图、输入采样及曲包安装；只有语义一致时直接复用。
- **原生扩展数据**：为音符保留源实体 ID、group ID、stage ID 和必要的原生行为；旧谱面未携带数据时走原路径。禁止用全局静态开关影响其他会话。

### 3.2 技能与 Fever 的明确处理

仅将 `Skill`、`FeverChance`、`FeverStart` 加入明确的忽略名单，记录到兼容报告的“按项目约定忽略”项。它们不创建音符、计分点、特效、音效或事件，也不启用加分、回血、判定辅助、Fever 槽和任何倍率。

语法解析和文件资源上限仍生效；忽略实体内部的业务字段不要求被本项目理解。其他实体若引用被忽略实体，应检查引用实际用途，不能将无效引用当作合法音符或舞台引用。未知 archetype 不得顺带忽略。

成绩展示采用项目约定的无技能、无 Fever 规则，不能宣称数值与开启这些机制的 Sonolus 成绩一致。相关规则写入成绩档案，而非悄悄修改谱面原始数据。

## 4. 关键功能设计

### 4.1 音乐偏移与统一时钟

保留 `bgmOffset`，不写入旧 `fillerSec` 抹平差异，也不重复加到音符、音频和输入三处。建立一个明确的音频时间与谱面时间映射，并分别派生逻辑时钟和画面时钟。

实施前通过官方定义、上游运行参考和带已知点击位置的合成音频确认正负号。文档中写清“音频第 0 秒对应谱面哪个时间”，再用 ±0.51 秒、±1 秒、0 的用例锁定方向。当前官方 LevelData 类型页只给出字段结构，不能仅据字段名猜符号。

时钟改动需覆盖：负时间预滚、音频尚未开始、音乐先于第一判定点、暂停/恢复、重开、可用的跳转路径、音频结束后仍有判定点。梳理现有时间下限为 0 的截断，保留旧谱面默认行为。音乐偏移、玩家音频延迟、画面延迟和判定偏移各应用一次，自动播放按既有约定不应用玩家判定偏移。

### 4.2 分组变速

现有“整体事件时间线 × 单 note 固定倍率”保留给旧谱面。原生音符改为引用所属组，每组拥有独立事件链；它不是在全局速度上重复乘一次组速度。

编译各组的 BPM 换算时间、事件链、累计坐标及缓动参数，提供统一的距离/进度求值。完整实现 `#TIMESCALE`、`#TIMESCALE_SKIP`、`#TIMESCALE_EASE`、`transitionStyle`、`hideNotes`、`forceNoteSpeed` 的基线语义。`editorName`、`editorHidden` 归类为编辑元数据。

不能简单把当前组倍率代入现有公式：出现时间、长条两端位置、skip 和回头路径都依赖整段轨迹。普通连续滚动可用积分距离解释；TIMESCALE 与 SCROLL 模式混合时应以基线上游算法为准，不预设两者可用同一个积分式覆盖。

停止和倒流时不得因“时间已过”或“当前不可见”永久回收仍可能出现的装饰。判定到期仍由真实目标时间驱动，视觉回头不能重复判定或加 Combo。按组缓存每帧求值，使用预编译索引，避免每个音符每帧扫描全部事件。

### 4.3 锚点、连接与隐藏点

将“几何连接图”和“可计分判定图”区分开。保留 `head/tail`、`segmentHead/segmentTail`、`activeHead/activeTail`、`next/prev` 的不同职责，按实际规则校验，不强制这些引用全部相同。

- Anchor：复用隐藏中间点的不可见、不计分和几何属性，扩展其端点用途；不强制拥有普通长条父节点。
- Connector：独立保留片段类型、缓动、颜色、透明度、层级、展示方式、穿判定线与两端所属时间线/舞台。
- Guide：优先复用项目现有装饰条；装饰条的真实可判定尾仍保留判定权。
- 附着：统一求取 lane/size，供渲染与命中测试使用；支持曲线插值，不能继续全部按线性时间插值。
- TransientHiddenTickNote：有判定与计分，不能映射成无判定隐藏中间点；只使用谱面提供的判定点，不叠加旧自动生成点。

支持合法的同拍几何节点与零长度连接；判定链和几何图分别检测循环、共享关系、非法归属及缺失引用。拆分当前“一律严格递增”的限制，按实体用途实施约束。

### 4.4 全音符族与输入

建立“独立/头/尾 × Tap/Flick/Trace/TraceFlick/Release × Normal/Critical”的实际存在类型表，逐项对照上游；另列 Tick、HiddenTick、Damage、HiddenDamageTick、全部 Fake 与 Anchor 变体。不要假设所有组合都存在或语义相同。

沿用 press/release/resident 三条输入通道，补齐独立 Release、不同长条头尾和向下划键。对照上游输入分配、早触、松手、划动方向、条身覆盖与宽限，不因运行时类名相似就认为行为相同。自定义样式不得改变判定类别，Critical 的继承按源数据和 revision 明确执行。

Fake 只参与显示，不消耗玩家输入、不产生 Miss、分数或 Combo。Damage 按目标规则处理触碰/避让、伤害量、持续伤害时机、自动播放与镜像，并验证是否影响计分分母和 Combo；不能复用普通音符“命中就加分”的默认逻辑。

### 4.5 舞台、相机与样式

支持基线中实际用于 LevelData 的 `Stage`、`CameraChange`、`StageTransformChange`、`StageMaskChange`、`StagePivotChange`、`StageStyleChange`；确认 `StaticStage` 等名称是内部生成实体还是合法谱面输入后再定处理方式。

按源码顺序实现局部 lane/size、pivot、yOffset/yBeatOffset、elevation、舞台变换与相机投影。渲染和触摸命中共用相应变换约定；纯视觉 mask 与实际命中范围按上游区分，不能凭视觉裁切结果直接删除输入候选。

补齐 style、effectKind、segmentAlpha、segmentLayer、segmentPresentation、isSeparator 及动态颜色透明度。先保证几何与可辨识性，再对齐素材和特效。超出当前 12 轨、窄于一轨、零宽几何等数据按上游合法域处理，废除当前仅为首版加载器设置的限制；同时保留有限数值、内存与几何复杂度上限。

### 4.6 判定、生命与成绩

把原生规则接入会话级策略，旧谱面继续使用既有策略。逐项对齐输入窗口、方向检查、判定点权重、Combo、生命扣减、初始生命与结算，排除技能和 Fever 的影响。上游 ScoreMode 提供多种模式，完整范围应包含这些模式的明确映射与选择，不能将项目默认算法称为所有模式兼容。

原始压缩文件 SHA-256 继续作为谱面身份，不重新压缩、不改写实体。新增独立的规则标识与版本，包含计分模式、无技能/无 Fever 约定及影响成绩的玩法选项。保存成绩时同时保留谱面 key 与规则 key；旧记录缺失规则信息时归入 legacy，保留原始记录，不合并到新规则最好成绩。格式、来源和上游 revision 用于说明与诊断，不能依赖文件扩展名区分成绩规则。

每阶段完成实现、针对性测试和文档更新后提交。遇到语义差异先保留兼容诊断，再补实现；不能通过扩大忽略名单制造“可播放”。

| P3：锚点和连接 | 隐藏点复用、端点扩展、连接图、Guide、曲线、附着、透明度与样式 | Kamisama 实际使用的所有相关字段通过；隐藏计分点不增不减；同拍节点合法 |

## 6. 验证方案

### 6.1 合成测试与上游对照

所有数学边界先使用小型、可审阅的合成 LevelData，测试不依赖在线服务器。对照工具固定上游提交与选项，通过参考计算输出或 Sonolus 实机录制比对位置、出现时间、命中结果；自动播放完成只能证明生命周期，不能证明手动判定和画面正确。

| 领域 | 必测内容 |
| --- | --- |
| 解析/兼容 | revision 缺省与 0/1/2；重复名称/字段；缺失/错类型引用；业务忽略与未知实体区分；内部实体不误认为输入 |
| 时间 | ±偏移、负拍、跨 BPM、第一拍前输入、音乐尾后节点、L/V/J 组合、暂停/恢复、重开 |
| 轨迹 | 两组同拍不同位置；0/负/极大速度；skip；缓动边界；SCROLL/TIMESCALE 混合；同拍事件顺序；回头再入画 |
| 连接 | 锚点头尾/中间点、同拍段、曲线、变宽、附着、透明度/层级、装饰与真实节点混合、不同 group/stage 的端点 |
| 输入 | 每种键成功/早/晚/错误方向/未操作；一指多候选；抬手竞争；断触与重接；镜像；掉帧跨窗口 |
| 计分 | 每点只结算一次；Fake/Anchor 为零；隐藏 Tick 数量；Damage；初始生命；全部目标计分模式；忽略 Skill/Fever 后结果稳定 |
| 持久化 | 原始字节不变；规则 key 隔离；历史记录迁移；曲包安装失败保留旧文件；导出再导入一致 |

以节点目标时间、变换后边界、轨迹进度及最终判定事件作为断言，避免仅断言实现内部字段。时间数学使用 double；误差标准分别记录数学误差、float 运行时误差和设备音频延迟，不能用一个宽松误差掩盖三类问题。

### 6.2 真实样本

- **You're Walking Down The Hallway**：`UnCh-81fb32f7724a4a1eb92ddbbe045082c9`；基础可玩与 848 判定点回归。
- **Kamisama**：`UnCh-c22c3d9ac1e94636a10cea38591f6b9a`；偏移 −0.511 秒、两组变速、51 个 Anchor；验证实际事件边界与路径。现有曲包位于本地 `.utmp/downloads/`，不提交媒体。
- **LifeResetButton**：`UnCh-690d4ea6de0443399b9d8f4be42f815b`；既有调研记录偏移 1.271 秒、8576 实体、136 个变速事件、4997 个 Anchor，用于复杂度与组合行为验证；实施时按资源 hash 核实样本版本。
- 补充包含向下划键、Damage、Fake、动态舞台的真实样本。网上样本不足时使用公开可分享的最小自制谱；记录测试范围，不能用未触及该能力的样本宣布通过。

样本元数据、hash 与合成谱进入测试档案；有权分发的小型合成谱可入库，第三方音频和完整谱面使用本地外部样本路径。在线下载测试与离线回归分离。

### 6.3 设备和性能

Windows 与至少一台代表性 Android 设备，记录设备型号、分辨率、刷新率、音频输出方式和构建版本。覆盖 30/60/120 Hz 的时间步模拟及实际设备支持的刷新率，验证密集连接、倒流重入、旋转舞台、暂停恢复和长时间音画漂移。

P0 先采集旧版和当前原生路径的加载耗时、峰值内存、每帧 CPU/GC、绘制数量，P2/P3/P5 后按同样设备重测。目标为参考 Android 设备 60 FPS（帧预算 16.7 ms），稳态原生轨迹与几何求值无新增持续 GC；预算最终以记录的设备基线确定。禁止为性能静默删除可见连接或判定点；超出明确资源上限时在加载阶段报告。

## 7. 发布验收

- [ ] 固定版本的输入实体、字段、枚举、默认值与 revision 差异清单全部完成，范围内无未实现条目。
- [ ] Skill、FeverChance、FeverStart 仅出现在约定忽略报告中，没有玩法或成绩副作用。
- [ ] Kamisama 与复杂样本原始包无需修改即可正确播放，画面经过上游参考核对。
- [ ] 全音符族通过自动和手动输入测试，装饰、Fake、隐藏判定点与伤害类型统计正确。
- [ ] 正负偏移、分组变速、动态舞台组合成立；暂停恢复无累计漂移。
- [ ] 旧 JSON / SUS 回归通过，旧成绩保留，新规则最好成绩分开计算。
- [ ] 完整 EditMode 与必要 PlayMode 检查通过，Windows / Android 手动验收留有记录。
- [ ] 性能与资源上限达标；未知后续版本给出具体兼容诊断，不崩溃或静默丢玩法。
- [ ] 更新现行支持文档、用户说明及样本档案，明确无技能/无 Fever 和素材替代约定。

## 8. 风险与实施原则

| 风险 | 处理 |
| --- | --- |
| 服务端引擎与 GitHub 基线不一致 | 保留 engine 资源 hash，先复现差异再决定兼容档案 |
| 旧时钟的非负假设散落在多处 | P1 集中梳理时钟和生命周期，以旧谱面及正负偏移一起回归 |
| 既有长条类把几何和判定绑定过紧 | 按需提取几何求值，不把 Anchor 伪装为会 Miss 的普通键 |
| “同名音符”实际判定不同 | 会话级规则策略和输入轨迹对照，不修改全局默认规则 |
| 多组倒流与大量曲线引发扫描/绘制开销 | 分组缓存、事件索引、可见区间和曲线误差控制；定量回归 |
| 实现升级后旧成绩看似可比较 | 原始谱面 hash 保留；规则版本单独存储；旧记录归入 legacy |
| 上游素材与逻辑许可不同 | 记录源码许可和必要署名；媒体不随测试自动入库，替代素材保留玩法信息 |

不以取消校验、忽略全部未知字段、把所有节点变成普通 note、仅自动播放成功或只跑一张真实谱作为完成依据。
