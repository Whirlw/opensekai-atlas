# 打歌材质包后端实施方案（ZIP v1）

2026-11-20 · 分发路线与 v1 目标契约。2026-11-21 已接入打歌音效、COMBO 标签和数字、[判定文字](../operations/material-pack-judgment.md)、[判定特效](../operations/material-pack-hit-fx.md)及[音符皮肤](../operations/material-pack-notes.md)。当前支持的槽位、样包使用方法与其余消费点见[音效样包与首轮清册](../operations/material-pack-audio.md)和 [COMBO 制包说明](../operations/material-pack-combo.md)。

**采用 ZIP 分发普通媒体，以 JSON 描述素材用途、布局和演出。** 一个 ZIP 可以包含两套 notes、一套判定字和多种音效；玩家按类或按单项组合，进打歌前生成一局专用的绑定表。制包只需要能输出 PNG、WAV 和 JSON 的工具。项目现有美术导入脚本继续制作内置素材和验收基准。

这条路线的主要成本在运行时：网格要能使用外部纹理，预制体中的引用要按使用处替换，循环音和结算演出要有明确的停止与释放时机。首个里程碑用同一份 ZIP 在 Android 上贯通这三条链路，再冻结公开格式。

## 覆盖范围与现有接入点

以下九类可独立选择。槽位表示用途，例如 `judgment.perfect`，与工程路径、文件名和 Unity GUID 解耦。一个槽位只归一类；判定字、COMBO 和两类特效各自独立于 HUD，结算音归音效。信息页排除在注册范围外。范围按打歌及其结束演出理解，曲目 BGM、谱面及曲目信息属于曲包内容。交付范围包括客户端本地后端及现有视图消费接口，选择页面和编辑器界面另行开发。

| 类别 | 实施入口与覆盖检查 |
| --- | --- |
| 背景 | 在 `Background2DView` 按组内 `layers` 从后往前合成普通 PNG 层和当前歌曲封面层。各层独立设置位置、大小及遮罩；`preferVideo` 决定有可用 2DMV 时是否优先播放视频。合成图沿用背景亮度和开场淡入。[背景皮肤制包说明](../operations/material-pack-background.md) |
| Notes | 从 `NotesViewManager`、各 NoteView 和 `PairNoteLineView` 对齐两套内置皮肤的音头、方向箭头、长条、尾部、中继、同时线，以及 NextRUSH 的实际绘制分支。为网格提供纹理矩形和 UV 映射，验证变宽、转向、拉伸时的接缝。 |
| 轨道 | 在 `LaneView` 映射底板、分道线、判定线和相关遮罩。偏移、轴心和缩放作用于视觉子节点，触摸投影仍由玩法坐标计算。 |
| HUD | 分数、评级、生命、暂停／跳过、两种 AUTO 标识和倒计时按槽选用图片及布局。进度条仍按实时数值填充，按钮随显示位置计算点击范围。[HUD 皮肤制包说明](../operations/material-pack-hud.md) |
| 音效 | 以实际播放的 cue 为槽位，覆盖敲击、滑动、长按循环、受伤、倒数和结束等声音。现有 `ExternalSoundPack` 会按 bundle 向 `AudioCatalog` 注册整组声音；新增当局逐 cue 查询，缺项走原播放路径，保留类别音量、循环停止及播放时机。 |
| 判定字母／文字 | `JudgmentView` 在建立结果字典时绑定当前六档主文字（含 Auto），覆盖快慢提示的实际显示入口。验证 Auto 显示设置及同档连续刷新。 |
| COMBO | `ComboView` 分别绑定标签、0–9 字形、普通／AP 样式与光圈。按字形记录步进和间距，验证首局、跨位数及掉连重置。 |
| 判定特效 | 从 `TapEffectView`、`LongTapEffectView` 及 NextRUSH 触发路径登记瞬发、持续、释放和轨道反馈。既支持替换内置模板的纹理，也支持替换整个事件的可视演出。 |
| 结算特效 | 五种结果分别支持模板布局、文字与粒子用图，以及整段多层序列。开局固定选择，沿用原有结算音、触发和退出时序。[结算特效制包说明](../operations/material-pack-result-fx.md) |

实施首项交付为逐槽清册，记录每个可见／可听素材的 key、状态变体、实际调用处、内置来源、类型、坐标空间和测试场景。用预制体序列化引用、图集取名、运行时加载、程序生成网格及音频清单交叉核对。逐项记录共享图、着色参数、程序化效果对应的替换入口；以完整清册验证“全部”，表里的例子只用于定位入口。

## 包格式与组合规则

根目录固定为 `pack.json`，路径相对包根。一个包有稳定的 `packId`、作者版本及多个带稳定 ID 的资源组；每组只属于一个类别，可仅提供其中几个槽位。不同组可引用同一文件。下面是一份可解析的v1 清单示例，展示同包跨类和局部覆盖。

```json
{
  "schemaVersion": 1,
  "packId": "example.ink",
  "version": "1.0.0",
  "groups": [
    {
      "id": "ink-judge",
      "category": "judgment",
      "slots": {
        "judgment.perfect": {
          "file": "images/perfect.png",
          "pivot": [0.5, 0.4],
          "offset": [0, 18],
          "scale": [1.1, 1.1]
        }
      }
    },
    {
      "id": "dry-hits",
      "category": "audio",
      "slots": { "audio.tap": { "file": "sounds/dry.wav" } }
    }
  ]
}
```

选择配置按类别保存有序的资源组引用（包 ID、安装修订、组 ID）及可选的逐槽指定。**逐槽指定优先，其次是该类列表中靠前且提供该槽的组，最后是本局原本会用的内置资源**。逐槽可显式选回内置；空列表且无逐槽指定时，整类沿用内置。选中的条目整体生效，省略的变换继承槽位默认值。这样 A 包补敲击音、B 包补长按音时，不会因为二者都属于音效而互相清空。解析器应能返回每个槽位最终来源和回退原因。

| 配置 | v1 契约 |
| --- | --- |
| 切片与中心点 | 单图默认取全图；图集矩形用原图左上角像素 `[x,y,w,h]`。切片内的 pivot 用左下原点归一化坐标，默认取槽位中心点定义。上下翻转只在图像适配层转换一次。 |
| 位置与缩放 | 每槽声明参考框、锚点和默认尺寸。HUD／判定／COMBO／全屏演出以参考画布高度 1080 等比换算，横向锚到当前安全区；音符、轨道及跟随特效在局部轨道坐标中以一条 lane 的宽度为单位。偏移向右／上为正。先按参考框适配，再绕 pivot 缩放，最后将 pivot 放在锚点加 offset 处。所有计算取布局基准，避免池化复用累计偏移。 |
| 类型差异 | 精灵可声明适配方式、切片边界；数字可声明 advance；网格按槽支持 UV、端帽和可拉伸段。整屏背景可选择等比填充或完整显示。音频声明文件及适用的循环区间；每类只接受可执行的字段，越界或不适用字段给出定位诊断。 |
| 特效 | 首版提供内置模板贴图替换和声明式分层序列帧两种表达。每层定义帧、每帧时长、锚点及变换；持续特效支持进入、循环和释放段，绑定既有开始／结束事件；结算动画限定在游戏所给的可播放窗口，跳过时立即回收。包只携带数据及媒体。 |

### 作者交付契约

| 对象 | v1 约定 | 校验与编辑器行为 |
| --- | --- | --- |
| ZIP / 清单 | 包根唯一的 `pack.json`，UTF-8。媒体可分目录，引用使用包内相对路径和正斜杠，区分大小写。 | 根清单缺失、规范化后同名、仅大小写不同的两个文件或引用越界，整包安装失败。编辑器导出时进行相同检查。 |
| 包和组 | `schemaVersion` 为整数；`packId` 与组 `id` 使用小写 ASCII 字母、数字、点、短横线，以字母开头。作者发布版本 `version` 为字符串。组 ID 在本包内唯一，可选 `displayName` 供将来的选择器显示。 | 选择记录引用稳定 ID，改显示名不影响组合。包摘要取排序后的规范路径及各文件内容摘要（长度前缀编码），同一内容换压缩级别或 ZIP 时间戳仍视作同一修订。 |
| 类别与槽位 | 九个类别 ID 为 `background`、`notes`、`lane`、`hud`、`audio`、`judgment`、`combo`、`hitFx`、`resultFx`。槽位由游戏目录发布，带类别、媒体类型和允许字段。 | 同一组内重复 JSON 键、类别与槽位不符、未知槽位均报错。同槽出现在同包不同组合法。 |
| 图片 | PNG 单图或 PNG 图集，支持透明；静态图可写 `rect`。精灵尺寸按槽位的逻辑参考框计算，作者可用高分辨率图保持相同视觉尺寸。 | 检查真实编码、图像尺寸、切片范围、正数缩放、有限数值及 pivot 范围 [0,1]。同一图集只解码一次，各切片保留自己的布局。 |
| 声音 | 对齐项目素材约定，使用 16 位 PCM WAV，44.1 或 48 kHz，单／双声道。单次音默认从头播放；循环槽可指定 `loopFrames: [start,end]`，单位为每声道采样帧，左闭右开，省略即整段循环。 | 用文件头验证格式和帧数。循环段须非空且在文件内。释放、重开与暂停恢复复用原有声音事件及音量路由。 |
| 版本和扩展 | v1 只执行槽位登记的字段；可选 `extensions` 对象用于作者工具的命名空间元数据。 | 拼错的播放字段报错；编辑器读写保留扩展数据。较新 schema 返回所需版本，旧运行时跳过安装。 |

### 声明式演出如何落地

下面是一个 `resultFx.allPerfect` 槽位值。图片为 768×128 的三格图集，帧矩形单位为像素。作者可预渲染文字或粒子到帧中；同一演出可叠加多个层。

```json
{
  "kind": "sequence",
  "layers": [
    {
      "file": "fx/ap.png",
      "anchor": "center",
      "pivot": [0.5, 0.5],
      "offset": [0, 24],
      "scale": [1, 1],
      "frames": [
        { "rect": [0, 0, 256, 128], "durationMs": 80 },
        { "rect": [256, 0, 256, 128], "durationMs": 80 },
        { "rect": [512, 0, 256, 128], "durationMs": 240 }
      ]
    }
  ]
}
```

层按数组顺序从后往前绘制，各自从事件开始计时，用累计时长定位当前帧；低帧率跨过多帧时直接取当前帧。单次层播完隐藏，最后一层结束即归还实例。持续反馈的层可用 `loopFrameRange: [start,end]` 指定循环帧下标（左闭右开），开始时播放前段，持续时重复区间，收到释放事件后从 end 进入尾段。暂停冻结游玩特效，重开和跳过立即停止。结算类型、触发时间及可跳过窗口由游戏决定。

同一事件还可登记一组内置模板部件槽位，例如横幅或粒子纹理。解析先看“整段演出”槽：若有可播放的 sequence，只播放该演出；否则实例化内置模板，再绑定选中的部件。来源报告标出被整段演出遮住的部件。整段资源损坏时走同一模板回退路径。如此可避免自定义 AP 和内置 AP 同时出现，也允许玩家仅换横幅。

| 当前设置 | 最终应观察到的结果 |
| --- | --- |

## 安装、切换与开局

1. **安装。** 从本地 ZIP 导入同卷临时目录，复用并核对 `SafeZipExtractor` 的已有能力。验证规范化后的相对路径、重复项、文件数量、解压总量、图片解码尺寸、音频时长与内存预算，再验证清单、媒体类型、切片和引用。失败返回含组、槽、文件的错误；验证通过才发布版本目录并原子更新安装索引。用内容摘要标识不可变修订；重复导入幂等，同 ID 新内容新增修订。
2. **修改。** 后端提供列包、列组、校验组合、保存选择、恢复内置和卸载接口。打歌界面外可直接修改并持久化。保存与开局捕获在同一串行边界排序，调用者能获知此次保存对应的版本。更新可将现有选择一次迁移到新修订，缺失的组或槽先报告并保留旧选择；卸载同时修正下一局选择，旧修订在最后一个使用者释放后回收。
3. **开局。** 在 `PlayService.StartAsync` 捕获设置时一起捕获选择，解析出固定的槽位表。预载选中媒体、按文件去重、建立当局材质和声音映射后，再随 `PlaySession → LegacyLiveBootAdapter → FreeLiveBootData` 交给游戏侧。描述与组合逻辑独立于 Unity；引擎侧只依赖已解析的会话接口，维持现有程序集依赖方向。
4. **生效边界。** 从开始载入到暂停、恢复及本局结算结束，共用同一快照。打歌中管理写入返回“本局进行中”；在独立结算页面若可改选择，仍只影响之后新建的会话。当前暂停重开由 SoloLiveController.OnRetry 原场景复用 BootData 和视图。重开时核对选择修订：局内禁止改选，因此可复用同一套已加载资源，重置每个动画、声音和池对象；从曲库或独立结算页发起的新开局重新捕获。游玩热路径只查已绑定的句柄，禁止在击打时解 ZIP、读盘、解码或生成材质。
5. **失败与释放。** 若已安装资源损坏或丢失，开局按槽回退内置并汇总诊断；内置必需资源也失败时返回现有开局错误。取消开局、场景切换失败、跳过结算均释放已取得的资源。先停止循环音和池化特效，再释放 clip、纹理和实例材质；共享资源按修订和导入参数计数，避免旧局清理误伤新局。启动时清理未发布的暂存目录，恢复最近一次完整提交的索引与选择。

### 持久化与故障恢复

在应用私有持久化目录中划分 `material-packs/staging/`（临时导入）、`installed/<packId>/<digest>/`（不可变内容）与 `state.json`（已发布的索引、选择和单调递增的修订号）。索引与选择同一次原子替换，避免卸载后选择仍指向旧目录。先完整写入新目录，再提交状态，最后回收无引用目录。异常断电后只信任最后一个有效状态及其备份；遗留的暂存或未引用版本可清理。新版本安装默认只增加可选项；替换当前组合须显式保存，升级失败可继续使用旧版。

现有 `SafeZipExtractor` 已检查路径越界、符号链接、文件数、声明与实际解压字节以及剩余磁盘空间。其通用上限为 4096 项、单文件 512 MiB、总计 2 GiB。材质包应在解压前另做媒体专用预算检查，并在验证真实媒体头时复核；Android 的可用空间先在 Unity 线程查询，再交给后台解压。磁盘预算按整个安装包计，**运行时预算按选中组合解码后的资源计**：多个单独合格的包也可能组合超限。保存选择前返回超限项、估算值和预算，保留最近一次有效选择；内置基线开销纳入测量。

### 后端调用边界

下列名称用于描述契约，实施时可沿用仓库命名。所有管理接口均可从测试直接调用。

| 操作 | 输入与返回 | 提交点与失败语义 |
| --- | --- | --- |
| Validate / Import | ZIP、取消信号 → 包摘要、组与槽位列表、诊断；Import 另返回安装修订 | Validate 不写状态。Import 校验全包后一次发布，取消或单一坏引用均保留原索引。 |
| List / Resolve | 已安装目录、候选选择、当前内置套装 → 最终槽位、来源、冲突和预算 | 无副作用，供未来选择器预览，也作为开局解析的同一实现。 |
| SaveSelection | 完整候选组合、调用者上次读取的状态修订 → 新修订 | 修订过期则返回冲突及当前修订，防止旧页面覆盖较新的选择。局内写入返回忙。 |
| Uninstall | 指定包及修订 → 受影响的组、逐槽覆盖和新修订 | 提交时移除失效引用，重算候补组或内置；仍有快照占用的文件延后回收。 |
| Prepare / Release | 捕获的选择、谱面上下文和取消信号 → 每局资源句柄及回退报告 | 后台读盘和校验，在 Unity 允许的线程创建纹理、精灵、材质和 clip。转交开局前失败由创建方清理，转交后由会话持有者释放一次。 |

接入 `PlayService` 时，在读取 `PlaybackSettingsSnapshot` 的边界固定选择修订和版本引用；曲谱准备完毕后按实际玩法分支预载。将准备失败接入现有取消与回滚路径，只有 `_boot.Publish` 成功并接受场景跳转才完成所有权转交。材质包诊断单独返回，避免被现有谱面 JSON 或曲包 I/O 错误提示吞掉。声音在 Live 播放入口先查当局 cue，菜单与曲目 BGM 继续使用原目录；混用 custom01/custom02 同名 cue 时按本局原选套装回退。

## 后续编辑器如何复用

将清单解析／写回、槽位目录、布局计算、验证、冲突解释、ZIP 导入／导出作为可独立调用的库。目录能查询允许的媒体、单位、默认值及示例，编辑器据此生成属性面板；预览传入同一槽位、参考框和变换即可复现运行时布局。结构化诊断返回错误码、JSON 路径和媒体路径，供编辑器直接定位。用一个“解包 → 改单个 pivot → 导出 → 重新导入”的契约用例验证其他组、引用、选择结果和媒体摘要一致。区分格式版本与作者发布版本，对不支持的格式给出明确诊断，避免编辑器写回损坏较新包。

## 分期与验收

| 阶段 | 交付与过关条件 |
| --- | --- |
| P0　覆盖清册与可行性样包 | 对齐九类消费点，取一条长条网格、一位 COMBO 字形、一段循环音和一段完整 AP 结算做纵向验证。Android 上记录默认与样包的开局耗时、纹理／音频峰值、演出帧耗和连续重试后的占用，据此确定并公布包预算，冻结坐标与特效格式。 |
| P1　包与会话后端 | 实现清单、注册表、安装事务、来源解析和快照。自动验证同包多组、跨包混搭、逐槽恢复、同名冲突、重装、升级中断、坏包、取消开局、修改与捕获并发；重启后能复现所选组合。 |
| P2　背景、轨道、notes | 实现精灵、网格和层级绑定。在不同宽高比、两套内置皮肤、普通谱与 NextRUSH 谱中对比固定时刻画面；偏心 pivot 和非等比缩放在首帧、池化复用后均正确，固定输入回放的判定与分数一致。 |
| P3　HUD、判定字、COMBO、音效 | 同一局只换 PERFECT、一个 COMBO 数字和敲击音，逐项核对其余回退来源；随后整类替换。覆盖普通／AP、Auto、倒数、长按中断、暂停恢复。真机比对打击音反馈延迟、循环尾音及首局字形尺寸。 |
| P4　两类特效及整体验收 | 逐条触发判定事件、五类结算和跳过。每一类单独启用一次，九类同时启用一次，再用跨包混搭和逐槽冲突用例验证。完成 A 局 → 局外改选／卸载 → B 局 → 恢复内置，含重试、失败返回、进程重启；两局素材和声音无串用，信息页截图一致。 |

工作量集中在 **P2 的网格与 P4 的特效映射**。两者都需要对真实绘制结果验收；导入成功或清单覆盖率无法证明画面已替换。P0 未取得设备数据前，安装上限、内存预算和排期均为待验证项。最终以逐槽覆盖清册、自动化结果和 Android 视听记录共同验收。

### 验收证据与放行条件

- **纯数据测试。** 九类各取一个代表槽，用启用／内置两种状态穷举 512 种组合。逐槽比对来源并检查选择保存、重启、重新解析后一致。另测同类多组顺序、逐槽强制内置、资源损坏、跨修订引用及编辑器导出往返。
- **PlayMode。** 使用带明显颜色、非对称 pivot 和可区分声波的样包。记录视图实际绑定的纹理、UV、字形步进和播放的 clip。对同一谱面运行固定输入，核对音符命中、连击及分数；同时检查画面和音频确实发生了预期替换。将共享图集的同名资源在信息页作负对照。
- **Android。** 同一设备、画质、谱面和速度下，比较内置、局部覆盖、九类完整覆盖三组。分别记录冷开局与热重开、击打密集段的帧耗 P95 / P99、触发至出声延迟、解码期间内存峰值及连续十次开局退出后的存留。按长按、断连、暂停重开、五类结算和跳过保存截图或录音。P0 记录设备和基线、约定指标上限，P4 用相同条件复测。
- **发布门槛。** 九类逐槽清册中，每一项都有关联的绑定入口、样包条目和验证证据。若某个内置效果只能整段替换，在目录中明确整段槽及可独立替换的部件。覆盖缺口、性能超限或退出后资源持续增长都回到对应实施阶段处理。
