# 个人信息、成绩与段位方案

状态：设计草案，2026-11-22。首版面向 Android 本地玩家档案。Best 30 按不同谱面计算；文中的成绩公式、徽章门槛和成就目标为首轮调参数值。

## 交付分工

**Claude 负责全部前端，我（Codex）负责全部后端。** 本方案的后端运行在 Unity 客户端本地，包括玩法逻辑、存储、Android 文件桥接和提供给页面的 C# 接口。Claude 拥有界面设计和实现决定权，包括布局、字体、配色、美术资源、文案、动效、手势、导航和多屏适配。后文的界面描述约定玩家要看到的信息和能完成的操作，具体呈现由 Claude 设计。

| --- | --- | --- |

| 打歌与结算 | 曲库和服务器入口共用的独立结算页、FC/AP 字标、评级图标、涨分与升级动画、跳过、重试和返回 | 接收游玩结束事件、统一 FC/AP 和入榜资格、计算单曲成绩与总分变化、保存并发布本局结果、处理保存重试 |

## 前后端接口与并行开发

Codex 先提供只读数据结构、操作接口和代表性样例。Claude 用同一组接口绑定样例与真实服务。页面可以在后端开发期间完成交互和动效。下表使用建议名称，列出实现时必须能取得的数据。

| 接口 | 前端读取或发起的操作 | 后端承诺 |
| --- | --- | --- |
| 个人档案与榜单 | 读取档案、Best 30、分页历史；修改头像、昵称和佩戴段位 | 返回头像 ID、当前总分、评级 ID、已获段位及所选牌面。榜单每行包含谱面键、名次、最佳局 ID 与贡献分；历史以局 ID 标识每次游玩。 |
| 单局结算 | 读取本局快照，保存失败时按局 ID 重试 | 返回结束原因、判定明细、达成类型、入榜资格与原因、基础分及奖励、同谱最佳与总分的前后值、增量、旧新评级 ID、新解锁项及保存状态。后端决定是否跨档；Claude 将评级 ID 映射到图标并控制动画。 |
| 段位定义与挑战 | 预览分享文本、保存或导出定义、开始或退出、订阅挑战状态 | 预览返回有序曲目、扣血表、牌面样式或字段错误。运行时返回挑战场次 ID、当前曲序、初始及剩余生命、资源准备状态；结束时返回逐曲结果、失败位置及授牌结果。 |
| 成就 | 读取列表和本次解锁项 | 每项返回稳定 ID、条件参数、当前值、目标值和首次解锁时间；Claude 提供对应文案与图标。 |
| 备份 | 请求导出、选择并预览备份、确认合并或取消 | 区分用户取消、读取失败和成功。预览返回新增、重复及冲突数和本次预览标识；确认时提交同一份预览，返回合并结果与最新档案。 |

首批结算样例覆盖普通通关、FC 同谱刷新、AP 新谱挤入第 30 名并跨档、刷新谱面纪录但总分持平、自动游玩以及保存失败。样例中的原始数据和预期数值由 Codex 提供，Claude 可直接切换场景预览。同一局重复打开时，存档去重由 Codex 保证，升级动画的一次性播放由 Claude 按局 ID 处理。

### 第一阶段联调入口

曲库与服务器都从现有的 `PlayResultHandoff.Take()` 消费一次 `PlayResult`，再把同一个实例传给结算页。下例可直接在预览里运行，样例只使用内存。

```csharp
using OpenSekai.App.Library;
using OpenSekai.App.Playback;
using OpenSekai.Shared.Playback;

PlayResult play = SettlementSamples.Create(SettlementExample.NewChartAllPerfectTierUp);
RankingSettlement ranking = CustomMusicScorePlayHistoryStorage.ForDisplay(play);
```

- 从 `play` 读取曲名、难度、原始分、连击和五档判定；`play.Award` 区分普通通关、FC 和 AP。真实加载失败也可交给 `ForDisplay`。
- 从 `ranking` 读取 `BasePoints`、`Bonus`、`Points` 和 `Eligibility`。前后状态 `Before` / `After` 均含总分、评级 ID（0 至 6）、该谱最佳和榜内名次（1 至 30，榜外为空）。`ChartImproved` 控制新纪录文字，`Delta` 控制涨分，`TierUp` 控制升级。
- 写入失败显示 `SaveFailed`，总分维持原值。真实结果可调用 `CustomMusicScorePlayHistoryStorage.RetrySave(ranking.PlayId)`，绑定返回的新快照。失败样例用于预览。成功保存后，从 `ReachedAchievementIds` 读取本局首次达成、等待解锁的成就。
- 榜单调用 `CustomMusicScorePlayHistoryStorage.ReadBest30()`，返回按贡献排序的只读快照。第一个条目为第 1 名，每项包含成绩分和对应的最佳历史记录。上述存储接口均在 Unity 主线程调用。

| SettlementExample | 成绩分 | 个人总分变化 |
| --- | ---: | --- |
| FirstClear | 267 | 0 → 267 |
| SameChartFullCombo | 272 | 同谱 267 → 272，+5 |
| NewChartAllPerfectTierUp | 310 | 7,790 → 7,850，+60，跨过 7,800 |
| OutsideBest30 | 172 | 榜外谱刷新，7,790 持平 |
| Auto / Failed / Retired | 0 | 自动、失败、退出分别展示原因 |
| SaveFailed | 272 | 267 持平，写入失败 |

### 第一阶段前端进度（Claude，2026-11-22）

结算页已接入，代码在 `App/UI/Result/`，替换了原来的 `LibraryResultPanel` 弹窗。

- **入口。** `LibraryView` 与 `ServerScreen` 各建一张 `ResultPage`，铺满自己的画布并盖住来源页；关闭后来源页保持原样。曲库从打歌返回时会重建，`LibraryPresenter.ShowResult` 会重新选中刚打的曲包并滚到它；服务器页面在打歌期间保留，返回后仍停在谱面详情。「再玩一次」沿用本局谱面与模式，「返回曲库 / 返回服务器」在左上角，安卓返回键同效。
- **读取。** 页面只调用 `CustomMusicScorePlayHistoryStorage.ForDisplay(play)`，不改动 `PlayResult` 与 `RankingSettlement`。没有记录器时 `ForDisplay` 会抛异常，读历史时也可能出现 IO 异常；页面会记录日志，并在成绩区显示「本局未记录成绩」，不会卡住。
- **时间线。** 分数计数、FC/AP 字标、成绩分、总分滚动和涨分标签依次出现，约 2.5 s 走完；跨档时追加约 0.9 s 的徽章升级：旧徽章放大发白，新徽章弹出，随后按新评级逐步展开。评级越高，飞出的六边形环（1–3 道）和火花（10–30 颗）越多，侧翼菱形从徽章后滑出，光芒旋入，页面角落的光晕以新评级的颜色闪亮。轻触空白处直接跳到定格并静音。升级动画按 `PlayId` 在本次运行中只播一次，重开同一局直接显示新徽章和「评级提升」标签。
- **保存失败。** 显示「成绩未保存」和「重新保存」，并调用 `RetrySave(PlayId)`。返回 `Saved` 后换成新快照，从成绩分开始重播涨分；返回 `null` 或仍未保存时保留原状并提示。
- **评级 ID 的呈现。** 前端名称与配色为 0 星尘 STARDUST、1 新星 NOVA、2 流星 METEOR、3 银河 GALAXY、4 星海 STARFIELD、5 天穹 ZENITH、6 寰宇 COSMOS（`RankingTiers`）。颜色从灰、薄荷、蓝、紫、玫红走到金，寰宇用 ALL PERFECT 的粉紫青渐变，评级名也按此着色。徽章都是六边形，和矩形的段位牌区分开。星尘是原来的平面徽章：着色的底、实线描边、细内线和中间一颗菱形。往上每档在下一档的基础上增加内容（`RankingCrestArt`）：中心菱形先变成四角星，再依次加上斜向短角、星环、环上四颗小菱形和短光芒；外围依次加上两侧的菱形列（流星一颗，到星海三颗）、外框（银河）、外框六个角上的菱形（星海）、旋转光芒和第二道内线（天穹），最后是全部描边改用渐变、第二道外框、穿过徽章的轨道与卫星和第四颗侧翼菱形（寰宇）。徽章上方不加顶冠。徽章越华丽，六边形略微缩小，以免压到上方标题和右侧文字。高档徽章在后台线程绘制，画好前先显示同色的平面徽章。门槛只由后端决定，前端不重复；如果档位数量改变，需要同步更新 `RankingTiers` 和 `RankingCrestArt`。
- **预览。** `Tools/capture-screens.ps1 -Result default,fc,ap,outside,auto,failed,retired,savefailed,loaderror` 逐个拍下样例的定格画面，`-ResultAt` 可以拍动画中间的帧。`-RankingTiers` 拍下七个评级的首页卡片、各尺寸徽章、每档升级动画的三帧，以及「评级徽章」弹窗的静止画面和寰宇重播的两帧。
- **未完成。** 成就提示等 `UnlockedAchievementIds` 有内容后再接，排在升级动画之后。验收表中「从两个入口打完同一谱只占一个榜位」还要在真机上用真实游玩核对。

### 第二阶段后端联调入口

个人页从 `OpenSekai.App.Library.PlayerProfileStore.Local` 读写本机档案。页面在 Unity 主线程发起操作。

| 页面操作 | C# 接口与返回值 |
| --- | --- |
| 打开个人页 | `Read()` 返回 `Appearance.Nickname`、`Appearance.AvatarId` 和 `Best30`（含总分、评级 ID 和榜单行）。初始昵称为 `Player`，默认头像 ID 为 `default`。段位数据随第三阶段接入，当前 `EarnedDanIds` 为空，`EquippedDanId` 为 null。 |
| 编辑昵称与头像 | `SetAppearance(nickname, avatarId)` 同时保存两个字段。头像由前端将稳定 ID 映射到内置资源。 |
| 查看游玩历史 | `ReadHistory(offset, limit)` 从零起算，返回 `Records` 和 `TotalCount`。按游玩 UTC 时间倒序，同时间按局 ID 排列。旧版记录可查看；Best 30 从 v3 起算。 |
| 导出 ZIP | `await ProfileBackupPicker.ExportAsync()`。系统选择器保存成功返回 true，取消返回 false。 |
| 选择并预览 ZIP | `await ProfileBackupPicker.PickImportAsync()`。取消返回 null。预览提供 `Id`、新增数 `Added`、重复数 `Duplicates`、冲突局 ID 列表 `ConflictingIds`、缺 ID 的历史行号 `MissingIdLines`（从 1 起算），以及合并后档案 `Result`。 |
| 确认或取消合并 | `ConfirmImport(preview.Id)` 返回已生效的档案，`CancelImport(preview.Id)` 丢弃预览。打开下一份备份、修改资料或在确认前新增游玩，均需重新预览。 |

两个选择器接口均可传入 `CancellationToken`，系统选择器由系统返回键取消。页面可在等待期间显示处理中。格式或 I/O 失败通过异常返回。已持有文件路径的调用方可直接使用 `ExportBackupAsync(path)` 或 `PreviewBackupAsync(path)`。

备份 v1 包含格式清单、头像昵称和完整可读的 JSONL 历史，以 SHA-256 校验内容，支持最多 64 MiB 的未压缩历史。已有游玩记录或已保存资料的档案保留本机头像昵称；空档恢复备份资料。本机历史为空时，缺少 ID 的旧版记录也逐条恢复。本机已有历史时，合并会跳过缺少 ID 的行，同 ID 冲突保留本地记录。只有确认才切换生效目录，重新启动后继续使用已确认的历史。段位定义、挑战记录和授牌将在第三阶段扩展备份格式。

### 第二阶段前端进度（Claude，2026-11-22）

首页第二页和个人页已接入。首页代码在 `App/UI/Home/`（`HomePager.cs`、`HomeView.cs`、`HomePlayerCards.cs`），个人页在 `App/UI/Profile/`。

- **两页首页。** 第一页是曲库、服务器、资源包，第二页是个人信息、段位、成就。翻页有三种方式：左右滑动、点底部「游玩 / 个人」标签、点屏幕边缘的箭头。手指横向移动超过 28 画布单位（手机上约 2 mm）后才算滑动，并取消卡片点击，在此之前仍算轻触。松手时拖过页宽的 18% 或快速甩动才翻页，否则回弹。竖向拖动不翻页，也不算点击。从个人信息返回时停在第二页；从设置打开资源包时先切回第一页。
- **段位与成就卡。** 两张卡都标「即将推出」，点击时卡片轻摇并提示，第三、四阶段接入。
- **个人信息卡。** 显示头像、昵称、佩戴的奖牌（最多两块，并排在昵称下方；都没戴时显示「未佩戴奖牌」）、Ranking Score 和评级徽章，以及 Best 30 谱面数和游玩次数。每次回到首页都从 `Read()` 和 `ReadHistory(0, 1).TotalCount` 刷新。读取失败时卡片显示「档案暂时无法读取」，首页不会卡住。徽章周围的星空随评级递增（`HomeRankingSky`），每档保留下一档的全部内容：星尘是闪烁的星点和两道轨道；新星加上从徽章扩散的脉冲，最亮的星变成四角星；流星加上划过的流星；银河加上第三道轨道和卫星拖尾；星海加上缓慢漂移的星点和星座连线；天穹加上旋转的光束和上升的光点；寰宇把这些都换成渐变色，并加上第二道脉冲和漂移的星云。
- **个人页。** 左侧是玩家卡，右侧切换 Best 30 和全部历史，两个列表都按需加载，历史每 50 条调用一次 `ReadHistory`。封面按 `ScoreKey` 匹配已安装的曲包，未安装的显示占位图。
- **评级徽章一览。** 点玩家卡上的徽章打开「评级徽章」（`RankingBadgeGallery`）：七个评级从星尘到寰宇排成一行，每格是结算页尺寸的徽章（带待机动画）、评级名、起始分数，以及玩家的位置：已达成、当前评级（整格着色并描边），或还差多少分。起始分数沿后端的 `NextTierThreshold` 逐档取得，前端不另存门槛。点某一格会重播该评级的升级动画，与结算页相同：先以下一档的徽章蓄力，再换成本档展开，并伴随升级音效；星尘没有下一档，直接在原徽章上播放。弹窗只读，备份进行中或档案读取失败时也能打开，失败时不显示位置。
  - Best 30 每行显示名次、曲名、难度等级、原始分、AP/FC/CLEAR 和成绩分。列表头写「N 张谱面合计 X」，它与左侧总分不一致时记一条警告日志。
  - 历史每行显示本地日期时间、手动或自动、连击、结束标签和原始分。正好是某谱贡献局的那一行标「Best 30 · 第 n 名 · x 分」，不计入的写明原因（旧版、自动、未完成、中途退出）。
  - 在「全部历史」中长按一条记录 0.7 秒，会弹出删除确认卡。「清空历史」始终可以点。系统成功保存当前历史的备份后，它打开清空确认卡。没有这样的备份时，卡片说明清空前需要备份，并提供「导出备份」，导出成功后回到清空确认。两种确认都沿用删除曲包的「再点一次确认」行，第一下变红并抖动，第二下才删除（`LibraryActionRow`，暂停卡也用它）。单条删除后，现有备份仍覆盖剩余成绩。写入新成绩或导入新增记录后，清空前需要再次导出。
  - 前端不计算成绩分，也不判断入榜资格，只按 `RecordId` 对照 Best 30 的条目。
- **头像与昵称。** 「编辑资料」卡提供 12 个内置头像，另有 3 个由成就给出（见[成就的等级与解锁](#成就的等级与解锁)）。内置头像的稳定 ID 为 `default`、`note`、`flick`、`hexagon`、`diamond`、`halo`、`wave`、`heart`、`globe`、`trophy`、`orbit`、`play`（`ProfileAvatars`）。头像全部用现有形状绘制，不附带图片。遇到不认识的 ID 时按默认头像显示，但保留原 ID，除非玩家另选。昵称在前端限制为 24 个字符，去掉首尾空格，过滤控制字符，空昵称不能保存。
- **备份。**
  - 导出调用 `ExportAsync`，成功、取消和失败分别提示。
  - 导入调用 `PickImportAsync`，等待期间显示处理中卡片，并可以取消。
  - 预览卡显示新增、重复和冲突局数，是否恢复头像与昵称，Ranking Score 前后值和评级变化，前三个冲突局 ID，以及缺少 ID 的行号。没有新增、也不恢复资料时，只给「知道了」按钮。
  - 「确认合并」调用 `ConfirmImport(preview.Id)`。抛出 `InvalidOperationException` 时视为预览过期，提示重新选择备份；I/O 失败时保留预览，可以再试。合并后个人页、首页卡片和曲库的游玩统计一起刷新。
  - 取消、按返回键或离开个人页时都会调用 `CancelImport`。
- **返回键。** 依次处理：备份进行中则取消，预览打开则取消合并，编辑卡打开则关闭，设置打开则返回上一层；都没有时回到首页第二页。
- **预览。** `Tools/capture-screens.ps1 -ProfilePage` 在临时目录生成样例档案和一份待合并的备份，不读也不改本机档案。它依次拍下第二页、滑动中途、卡片放大、Best 30、历史、编辑卡、合并预览、返回后的第二页和新档案。

| 操作 | 接口与行为 |
| --- | --- |
| 创建、粘贴、复制 | 用 `new DanDefinition(initialLife, damage, songs, label, emblem, color)` 构造定义。扣血表是 `OpenSekai.Shared.Playback.DanDamage(perfect, great, good, bad, miss)`。用 `DanDefinition.Parse(text)` 预览，捕获 `DanFieldException.Field` 定位错误（如 `songs[1]` 或 `damage.miss`）。复制 `definition.ShareText` 即可分享。相同谱面链接的 HTTPS、Sonolus 和分享包装形式归一为同一个地址。 |
| 保存与编辑 | `SaveDanDefinition(definition)` 按规范化定义去重。`ReadDanDefinitions()` 提供曲序、初始生命、扣血表和牌面字段。编辑后内容变化即有新 ID，原定义继续与原通关记录关联。 |
| 开始与重试 | 先订阅 `DanChallengeService.Local.Changed`，再调用 `await service.StartAsync(definition, token)`。返回的 `PlayStartResult.Started` 表示首曲已交给打歌场景。准备时按 `Phase` 和从 1 起算的 `SongNumber` 显示进度。失败时读取 `Error` 和曲序，修复后再次调用即可。全部曲目的谱面和音频在首曲前检查，本轮使用固定副本。 |
| 打歌与曲间 | `Definition.InitialLife` 是 HUD 分母，`RemainingLife` 是实时分子。`BetweenSongs` 时 `SongNumber` 已指向即将开打的曲目，休息最长 `REST_SECONDS`（50 秒），`RestRemaining` 给出剩余秒数，`ContinueNow()` 立即开打，`SongDirectory(n)` 给出第 n 首固定副本的曲包目录。主动退出调用 `Quit()`；暂停与恢复沿用当前打歌控制器，暂停菜单的重试从第一首另开场次。跨场景页面销毁时解除事件订阅。 |
| 结算与历史 | 终局读取 `Attempt` 和 `NewlyAwarded`，后者表示本次首次取得牌面。`ReadDanHistory()` 按开始时间倒序返回场次。每个 `DanAttempt` 有稳定 ID、定义 ID、开始时间、结局和逐曲明细。`SongNumber(definition)` 提供结束或中断位置；每曲含标题、谱面键、起始生命、结束原因、进度毫秒及五档判定等分数快照。强退后保留最近一个已落盘的曲界，未完成场次不授牌。普通历史和 Best 30 独立计算。 |
| 佩戴与恢复 | 佩戴统一走[奖牌](#奖牌)接口：`ReadMedals()` 列出已有奖牌，`WearMedal` / `RemoveMedal` 佩戴与卸下，`Read().WornMedals` 给出两个位置上的奖牌。`EarnedDanIds` 用于筛选已获段位。备份 v2 增加带校验和的 `dan.json`，仍可导入 v1。预览通过 `DanDefinitionsAdded`、`DanAttemptsAdded`、`DanDuplicates`、`DanConflictingIds` 展示段位变化。确认按钮绑定 `preview.HasChanges`，这样只有段位数据变化也能合并。空档恢复佩戴，已有档案保留本机选择。 |

运行中的页面以 `Phase` 驱动显示。首曲交接前会写入场次，随后在每首结束时更新；存档中的未完成场次统一标为 `Interrupted`。这样进程被杀后，历史仍能指出中断曲序。准备阶段取消可能没有场次，调用方先检查 `PlayStartResult.Status`。

- **佩戴。** `Medal.SLOTS` 为 2。`dan.json` 的 `Worn` 按位置保存奖牌键（`dan:<段位 ID>` 或 `achievement:<成就 ID>`）。`WearMedal(slot, key)` 指定位置，已戴在另一位置的奖牌与它对调，传 `null` 卸下；`WearMedal(key)` 放进第一个空位，满了换下第二块；`RemoveMedal(key)` 卸下。失去的奖牌不再显示，它的位置视为空位，重新取得后恢复。旧档案的 `Equipped` 读入第一个位置。空档恢复备份时一并恢复两个位置，已有档案保留本机选择。

- **等级。** `MedalGrades` 依次是 I 到 X、α 到 ω，共 34 级，显示在牌面右侧，可以不显示。
- **底纹。** 只有段位牌铺菱格底纹，文字和等级处变淡；其他奖牌是素底，色带里放成就的标记（10K、FC、AP）或奖杯。

- **绘制。** 边框按阶位和尺寸生成白色纹理再着色（`MedalFrames`），与奖牌颜色无关，同尺寸共用。

## 一、从首页到个人页

首页分为两页。第一页保留现有曲库、服务器和资源包入口；向左滑动，露出右侧第二页的「个人信息」「段位」「成就」。每页保留三个入口，并让玩家能发现另一页。拖动越过翻页阈值后取消卡片点击，轻触仍打开卡片。从三个新页面返回时停在第二页。

| --- | --- | --- |

## 二、单次成绩分与 Best 30

**每次游玩保留一条历史，每张谱面只占一个榜位。** 个人页同时提供「全部历史」和「Best 30」两个视图。历史按时间排列，Best 30 则展示名次、曲名、难度、原始分、FC/AP 标记和实际贡献的成绩分。

### 单曲怎么算

满分对应谱面的记分等级，每级 10 点。谱面等级超过 33 时，先加上超出部分的一半，例如 Lv.34 按 34.5 级、Lv.35 按 36 级计算。

| 百万制原始分 | 评级线 | 基础成绩分对应等级 |
| ---: | --- | --- |
| 900,000 | C | 记分等级 − 8 |
| 950,000 | B | 记分等级 − 6 |
| 975,000 | A | 记分等级 − 4 |
| 990,000 | S | 记分等级 − 2 |
| 1,000,000 | 满分 | 记分等级 |

低于 C 线的通关仍保留历史与达成标记，整局不参与 Best 30。各档等级下限为零，相邻两线之间按原始分线性插值，再乘以 10 并四舍五入。满分不同的记录按得分比例换算。FC 加 5 点、AP 加 10 点，每局取最高一档。Lv.31 的 S 线和 Lv.33 的 A 线都是 290 点。Lv.30 打到 980,000 分得 267 点，FC 得 272 点，满分 AP 得 310 点。

### 哪些谱面进入 Best 30

1. 开局时已确认 Ranked、有稳定谱面标识、难度与满分有效且达到 C 线的普通手动通关记录参加排名。未确认 Ranked 的手动成绩保留在历史中。失败、退出保留实际判定和结束原因。自动、编辑器测试、加载失败和段位挑战沿用各自的记录规则。谱面资格见[从服务器游玩和下载谱面](../guides/server-chart-downloads.md)。
2. 同谱判定首选项目已有的谱面内容键 `ScoreKey`。同一份谱面从曲库或服务器启动、移动安装目录、换封面或重装，均应归为同一张。不同难度若使用不同谱面内容，则分别排名。本地安装和服务器临时游玩均以原始谱面字节的 SHA-256 为键。
3. 先从每张谱的全部合格记录中取最高成绩分，再取最高的 30 张求和。只有 12 张时就加 12 张。总分相同的候选记录优先保留先取得的记录，再按稳定 ID 排序，反复开页或导入不会改变次序。
4. 不足 30 张时，新谱贡献全部成绩分。榜内已有谱从 267 提到 272，总分只涨 **5**。榜满后，新谱得 272、第 30 名为 264，总分涨 **8**。榜外谱即使刷新个人最佳，只要仍低于第 30 名，结算就显示「谱面新纪录」，Ranking Score 增量为 0。
5. 后端以 Best 30 总分计算评级。达到门槛即进入该档，例如从 7,790 分涨到 7,850 分会从流星升到银河。表中以 30 张谱面校准门槛，榜单未满时达到同一分数也会升档。已有档案直接按当前门槛计算。

| 评级 ID | 名称 | 总分区间 | 满 B30 的成绩基准（每张谱面） |
| ---: | --- | ---: | --- |
| 0 | 星尘 STARDUST | 0–5,999 | 初始档 |
| 1 | 新星 NOVA | 6,000–6,899 | Lv.24，A 线 |
| 2 | 流星 METEOR | 6,900–7,799 | Lv.27，A 线 |
| 3 | 银河 GALAXY | 7,800–8,999 | Lv.30，A 线 |
| 4 | 星海 STARFIELD | 9,000–9,899 | Lv.32，S 线 |
| 5 | 天穹 ZENITH | 9,900–10,499 | Lv.34，S 线且 FC |
| 6 | 寰宇 COSMOS | 10,500 及以上 | Lv.35，992,500 分且 FC |

## 三、独立结算页

保留打歌现场已有的收尾演出。演出结束或玩家跳过后，直接进入占满屏幕的结算页。曲库和服务器共用该页，返回时恢复打歌前的来源、列表位置或服务器详情；「再来一次」沿用本次谱面与游玩模式。独立页可放在现有 Library 场景内，通过页面导航替代两处弹窗。

| 区域 | 内容和显示时机 |
| --- | --- |
| 谱面与达成 | 封面、曲名、难度、原始分和现有单曲评价；FC 使用醒目的「FULL COMBO」标记，AP 使用独立的「ALL PERFECT」字标与配色。AP 优先显示，两个标记均可凭文字识别。 |
| 判定明细 | 最大连击、总物量和五档判定数。手动完成且全连才展示 FC；全曲均为 Perfect 才展示 AP，取五档中的 Perfect 总数。 |
| 成绩贡献 | 显示基础成绩分、达成奖励、该谱历史最佳和本次入榜情况。Ranking Score 区始终显示当前总分和徽章。涨分时显示「旧总分 → 新总分（+增量）」；本次不参与时标出原因。 |

结算消费一份不可变的本局结果，其中包含结束原因、唯一局 ID、落盘状态、该谱最佳的前后值、Ranking Score 的前后值和新解锁项。返回页面或重建 UI 只读取这份结果。写入失败时保留本局结果，显示「成绩未保存」和重试操作，成功保存后才展示已获得的涨分。

## 四、段位挑战

### 制作、分享与取得段位

制作页按顺序添加至少两首具体谱面的分享链接，可调整顺序，设置初始生命、各判定扣血和段位牌样式。段位名就是牌面文字；首版样式使用内置图案、文字和配色，这样复制一段文本就能在另一台设备还原。建议分享格式用带版本前缀的 JSON。下列为格式示意，链接仅为占位。

~~~text
OpenSekai-Dan/1
{
  "initialLife": 100,
  "damage": { "perfect": 0, "great": 1, "good": 3, "bad": 6, "miss": 10 },
  "songs": [
    "https://example.com/levels/chart-a",
    "https://example.com/levels/chart-b"
  ],
  "style": { "label": "双曲耐久", "emblem": "diamond", "color": "#526DC8", "tier": 2, "grade": "III" }
}
~~~

分享文本的业务内容只有这四项。`style` 里的 `tier`（阶位，0–4）和 `grade`（等级，`I`–`X` 或 `α`–`ω`）可以省略；取默认值时规范化后的文本不写这两项，所以没有阶位和等级的段位，文本和 ID 与加入它们之前相同。粘贴后先预览曲序、扣血表和段位牌，再保存到本地。对空曲单、单曲、非法链接、非正初始生命、负扣血或缺少判定给出对应字段提示。挑战身份由规范化后的定义计算；同一文本重复导入只出现一次。编辑一份已通关挑战会生成新定义，已取得的牌面及通关记录保留原版快照。

### 从第一首到最后一首

1. 开始前解析全部链接，优先命中本地谱面，缺失时复用 Sonolus 下载与导入流程。确认每首的谱面、音频和支持的引擎均就绪，固定本轮使用的内容版本。任一首不可用时指出曲序并允许重试，避免打到一半才发现下一首缺歌。
2. 整段只初始化一次生命。首版建议按顺序实际播放每张谱面，每首结束后进入最长 50 秒的休息页，显示下一首的信息和剩余生命，可以调整设置，也可以直接开始下一首，倒计时结束自动开打。每首使用自己的音频、时间轴与判定窗口；切歌不回曲库、不进单曲结算。生命延续，单曲分数和连击从头计算。
3. 每次有效判定只扣一次，最低为零。按五档判定读取扣血配置，装饰节点不扣血。NextRUSH 的伤害音符触发伤害时按挑战的 Miss 扣血一次，避开时不扣；接入时替换原有伤害分支，避免双扣。课程生命优先于谱面自带初始生命，HUD 分母使用整段初始生命。
4. 生命第一次归零即失败，即使发生在最后一键；最后一首完成且剩余生命大于零即通关。例：初始 100，首曲扣 37，次曲从 63 开始；再扣 63 就立即失败。暂停后恢复同次挑战，主动退出或进程中断记为未完成，再挑战从第一首开始。
5. 段位结算显示通过或失败、逐曲表现、剩余生命，以及失败所在曲目。首次通过授予段位牌，可当场佩戴。玩家可拥有多个自定义段位，并自行选择个人页和首页展示哪两块奖牌。

## 五、成就与历史统计

首版选能从本地历史准确重建的目标。条件用固定 ID、指标、门槛和文案描述。每条新记录只更新受影响的指标，进入成就页直接读取进度。

| 成就示例 | 建议计数口径 |
| --- | --- |
| 累计击打 10,000 键 | 累加手动判定的 Perfect、Great、Good、Bad。Miss、自动和装饰节点不计。这里的「键」指有判定的谱面音符，长按按实际判定节点计数。单曲失败或退出前已经打中的键也计入。 |
| 首次 FC Lv.25 及以上的谱面 | 首次达标显示解锁时间，AP 同时满足 FC 成就条件。 |
| FC 十张 Lv.28 及以上的谱面 | 按谱面键累计不同谱面数；同谱反复 FC 只贡献一张。 |
| 首次 AP、首次段位通关 | 分别取第一条有效 AP 和第一条通过的挑战记录。 |

建议段位中的有效击打同样计入累计击打；难度 FC/AP 成就取普通手动通关记录。段位总记录只负责通关成就，各曲明细负责击打，防止重复统计。同局同时解锁多个目标时合并提示；导入历史后展示一次汇总。

## 六、存档、回算与导入导出

- **历史是计算依据。** 扩展已有的 `PlayHistory.jsonl`，沿用 `recordId`、`sessionId`、`scoreKey`、`playLevel`、原始分与各档判定，补充结束原因、理论满分、成绩公式版本和可选段位场次/曲序。档案另存头像、昵称、佩戴选择、段位定义与挑战结果。计算出的 Best 30、徽章和成就进度均可从记录重建。曲库原有最佳原始分和个人最佳成绩分各按其用途比较。
- **新结构的起算范围。** 个人榜单从新版历史（schemaVersion 3）起算，包含五档判定和明确的结束原因。已有历史文件保留原样。重新启动后回放新版记录，得到同一份 Best 30。
- **一次结算只提交一次。** 开打时生成稳定的局 ID；结束时写入同一条结果，再更新索引。重试保存、切场景、应用重启或同份备份重复导入，都应得到相同的局数和积分。缓存落后于历史时从缺失部分补算，不在每次打开个人页时全量扫描。
- **导出。** 个人页生成带格式版本的 ZIP，包含个人资料、完整游玩记录、段位定义与成绩。使用现有 Android 系统文件选择器保存。备份里的曲目以稳定标识和标题快照引用，未安装曲包也能查看历史。
- **导入。** 先校验格式、版本和条目，再预览新增、重复和冲突数量。默认合并历史，新档案可恢复备份头像及佩戴选择，已有档案保留当前展示设置。以稳定局 ID 去重；同 ID 内容冲突时保留本地并列出冲突。缺少稳定局 ID 的条目在预览时标出。导入在临时目录完成合并和重算，成功后一次切换；取消、文件损坏或中断时仍可打开原档。导入完成显示合并摘要和新总分。
